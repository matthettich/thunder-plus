## Findings
1. WRONG AUDIO, confirmed by running (scratch test, not committed). live_host.cpp tryStartPlay (commitPlayFx, ~l.750) vs clearWaiting (called after applyOne returns, applyCommands). A play commits its own 33 effects plans, and only then does the clear of the waiting list commit any FxCommit that was waiting (future `at`). That FxCommit was planned BEFORE the play, so it lands after the song's plans and replaces the song's chain on that track. Test: fx_plan(0, delay) + fx_commit(0, at 2^40), then play(): 190803 of 192000 samples differ from a run without the stale edit. Fix: in tryStartPlay call clearWaiting(qStart) before commitPlayFx (or commit the pend_ FxCommits first). Same family: an FxCommit with future `at` followed by another commit with `at` NOW on the same track applies in time order, so the later plan's reuse_ entries find no slot (slot dropped, chain = the earlier plan's). No memory unsafety in either case: every plan is still committed and freed once.
2. Race FxHost `rand_` (read-only analysis, no TSan run). FxHost::plan (control, fxhost.cpp:154 via ModuleState) and FxHost::process (audio, fxhost.cpp:309) both point the thread-local wasi rand at the SAME `rand_`, `stmRng_`, `daisySeed_` (plain uint64/uint32, non-atomic). The control thread does make_fx (constructors call rand()), the audio thread runs effects that call rand() (Beads, Clouds, Cloud Seed, PitchShifter). Effect: lost or interleaved LCG updates, so noise and seeds are non-deterministic: wrong audio only (values, no pointers or indices), formally UB. Code is old (U14); it was unreachable while plan and render shared a thread, and P3 (fx_plan, play, plans while a host is processing) makes it real. Not a merge blocker; fix would be a per-plan scratch state (make on control with a private rand state, then copy in at commit). Related, by design: control CtlGate (fxpump.cpp:111) makes the audio thread pass a pump slot's sound for a block while play()/fx_plan makes pump instances.
3. Real-time audit, audio side: no new allocation, free, lock or syscall found. PdcPlan and MasterChainConfig are PODs (copies in tryStartPlay/adopt allocate nothing); FxBank::commitLive only swaps pointers and books lanes; plans return through fxBack_ and are deleted in collect() (live_host.cpp:125). The only allocation is the accepted FX1 one: a pump slot waking from rest or going bad does pump_free + pump_new in process (fxpump.cpp:290-292, 257, under PumpGate); nothing NEW. Live exposure is higher than in a render because plays restart often. Commit of pump slots makes no instance (made at plan time).
