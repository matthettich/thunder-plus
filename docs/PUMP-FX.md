# …pump effects in Thunder Plus (bus and master track FX)

The nine pump mastering plugins (`matthettich/pump`: EQ, COMP, LIMIT, CALM, TONE, BAND, WIDE, HEAT, METER) run in
Thunder Plus as track effects, on **bus tracks and the master** only. Stage 1 (23 Oct 2026) is the sound, the FX-screen
boxes and this interface. Stage 2 (23 Oct 2026) added the pop-up windows of EQ, COMP, LIMIT and METER, opened from the
FX screen's **› OPEN**, and the kit they share (`pump/ui/kit.js`, below under "The pop-up kit"); stage 3 (23 Oct 2026)
added CALM, TONE, BAND, WIDE and HEAT the same way, with `pump/ui/multiband.js` for what BAND, WIDE and HEAT share, so all
nine have their window. This page is everything a pop-up needs; it shouldn't be necessary to read the app's code.

## Where things are

| | |
|---|---|
| `pump/pump.wasm` | the plugins' own DSP: pump's `wasm/pump_wasm.cpp` (one C interface over the nine engines, each driven exactly as its `Plugin<Name>.hpp` drives it), built with `wasm/build.sh` (wasi-sdk 25, no threads: `PUMP_SYNC_KERNELS=1`). Loaded by the wasm loader as `pump/pump.wasm?v=1`. |
| `pump/pump-meta.js` | `globalThis.PUMP_META`: every plugin's parameter table and factory presets, generated by the same build from the plugins' `Params.hpp` (never edit by hand). `<script src="pump/pump-meta.js?v=1">`. |
| `index.html`, search `…PUMP` | the TFX types, the FX-screen boxes (`PUMP_BOX`), `window.PumpFX`, the worklet code (inside `TFX_SRC`), latency, the FX stage displays. |
| `pump/ui/kit.js` | the pop-up windows' kit (`window.PumpUI`): window manager, theme, controls, typed entry, menus, help, analyzers. Sets `PumpFX.openHook`. |
| `pump/ui/multiband.js` | `PumpUI.Multiband`: the crossover display, band regions, S / M / B strip and per-band listen that BAND, WIDE and HEAT share (a port of pump's `common/ui/MultibandUI.hpp`). Loaded after `kit.js`, before those three. |
| `pump/ui/<type>.js` | one window per plugin (`eq.js`, `comp.js`, `limit.js`, `meter.js`, `calm.js`, `tone.js`, `band.js`, `wide.js`, `heat.js`), each a port of the plugin's `plugins/<p>/UI<Name>.cpp`. Loaded by `<script src="pump/ui/…?v=N">` after the app's main script (search `…PUMP WINDOWS` in index.html). |

Rebuilding (keeps parity with the plugins): in the pump repo, `WASI_SDK=/path/to/wasi-sdk-25.0-x86_64-linux sh wasm/build.sh`,
copy `build/wasm/pump.wasm` and `build/wasm/pump-meta.js` into `pump/` here, bump both `?v=` (index.html, `sw.js`) and the
`sw.js` cache. `node wasm/compare.mjs` in pump checks the wasm against a native build of the same wrapper.

## Effect types and slots

`PumpFX.types` = `['eq', 'comp', 'limit', 'calm', 'tone', 'band', 'wide', 'heat', 'meter']`. The **type index** used in
telemetry is the position in this list. On the FX screen a slot's `f.type` is the TFX key `'p' + type` (`peq`, `pcomp`,
`plimit`, `pcalm`, `ptone`, `pband`, `pwide`, `pheat`, `pmeter`); `PumpFX.key(type)` and `PumpFX.typeOfKey(key)` convert.

A slot is addressed by **(track, slot)**: `track` 0 … 31 for a track (only buses can add pump effects; a slot keeps its
effect if its track later stops being a bus), or `PumpFX.MASTER` (= 32) for the master; `slot` 0 … 3.
`PumpFX.allowed(track)` says whether a track may add one now.

What a slot stores (in the song, saved with it, undoable like every FX edit):

| field | |
|---|---|
| `pump` | **every** parameter of the plugin, by its pump **symbol** (`threshold`, `b3_freq` …), in the plugin's own units. Symbols never change (pump's rule), so a song keeps working as the plugins grow (new parameters load at their defaults). |
| `on` | the slot's ACTIVE. It *is* the plugin's `bypass` (inverted): the worklet runs the plugin's latency-matched, crossfaded bypass, so switching never shifts the timing. Tracker FXO switches it too. `pump.bypass` itself is ignored. |
| `sel` | (EQ, BAND, WIDE, HEAT) the band the FX screen's band rows show, 0-based. Thunder's own, not a plugin parameter. |
| `sck` | (COMP) what feeds COMP's External sidechain: 0 none, 1–8 send n, 9 + t track t's own sound (as the MODFX slots' Source). Only heard when `sc_source` = External. |
| `pname` | the last preset applied (removed when a value changes). |
| `p_…` | the FX-screen boxes' hex bytes, mirrors of `pump` (don't use them). |

Parameter specs: `PumpFX.params(type)` = `PUMP_META.fx[type].params`, each `{s, n, sn, min, max, def, unit, scale, skew, flags, ch}`:
`s` symbol, `n` name, `sn` short name, `unit` one of `dB Hz ms % ratio oct x LU s` or `''`, `scale` `lin | log | pow`
(`pow`: `min + (max - min) · x^skew`), `ch` choice names (choice parameters only: value = `min + index`), `flags` the bit
mask of `common/PumpParams.hpp`: 1 automatable, 2 integer, 4 boolean, 8 output, 16 bypass, 32 hidden placeholder,
64 no-undo (listening/display state: solo, listen, delta, analyzer). The plugin's other metadata: `PUMP_META.fx[type]`
= `{name: 'COMP', long: 'Compressor', about: '…', params, presets}`.

## `window.PumpFX`

All functions take `(track, slot)` first and do nothing / return `null` when that slot isn't a pump effect.

| call | |
|---|---|
| `list()` | every pump slot in the song: `[{track, slot, type, on, key}]`. |
| `get(t, k)` | a copy: `{track, slot, type, key, on, values:{symbol: value}, sel, sck, preset, latency}`. |
| `set(t, k, {symbol: value, …}, opts)` | sets values (clamped and rounded as the plugin's host would; unknown and output symbols are skipped; `bypass` sets `on`). Returns what was applied. The FX-screen boxes and the bottom panel follow (redrawn at most every 80 ms). **`opts.live: true`** while a control is being dragged: the sound changes at once, the song is saved and the undo step is taken 350 ms after the last live set, so one drag = one undo step. Without it every call is its own undo step. `opts.src`: any value, passed to `onChange` listeners (to recognise your own changes). `opts.keepPreset`: don't clear `pname`. `opts.preset: 'name'`: set `pname` to that (a pop-up's own preset). |
| `setOn(t, k, on)` | ACTIVE. |
| `setSel(t, k, band)` | the band the FX screen shows (0-based). A pop-up that selects a band keeps the FX screen in step with it. It is a view, so it takes no undo step of its own (it is saved with the next edit); `onChange` gets src `'sel'`. |
| `setSck(t, k, v)`, `sckNames()` | COMP's External sidechain feed (`sck`: 0 none, 1–8 send n, 9 + t track t) and the names of the choices (`'NONE'`, `'SEND 1'` … `'TRACK 01'` …), as the FX screen's SC FROM. |
| `presets(type)` | `[{index, name, section}]`, `section` `FACTORY`, `SOURCES` or `CHAINS` (pump's preset menu groups, in its order). |
| `applyPreset(t, k, index or name, opts)` | as the plugin's preset menu: every parameter except output / bypass / no-undo / hidden goes to the preset's value or its default. Thunder's one difference: the CPU settings (`oversampling` of LIMIT and HEAT) keep the slot's value when the preset doesn't set them; `opts.keepCpu: false` applies the preset exactly as the plugin does. One undo step. |
| `subscribe(t, k, cb, {back})` | telemetry (below), about 31 times a second, for as long as you're subscribed. `back` (default 8192, at most 32768): how many past samples of each feed the first frame brings. Returns `unsubscribe()`. `cb({gone:true})` once if the slot is emptied or gets another effect (the subscription then ends). Survives the audio being rebuilt (it re-attaches every 500 ms). Several subscribers of one slot share the worklet's feed (it stops when the last one leaves). |
| `hold(t, k, kind, a, b, c, d)` | momentary listening, never saved or undone (see below). |
| `onChange(cb)` | `cb(track, src)` after any change of that track's effects from anywhere (FX boxes, presets, undo/redo, a load: re-`get` then; `src` is `'fx'`, `'latency'`, `'sel'`, `'undo'` (Thunder's undo or redo, sent for every track), `'load'` (another song) or your `opts.src`). Returns the remover. |
| `latency(t, k)` | samples: what the running effect reported, else worked out by a copy of pump.wasm on the page. |
| `format(type, sym, v)` | the plugin's display text (`'+3.0 dB'`, `'1.23 kHz'`, `'INF:1'`, choice names). |
| `toNorm / fromNorm(type, sym, …)` | 0…1 along the plugin's own control curve, and back (knobs, sliders, drags). |
| `clamp(type, sym, v)` | |
| `open(t, k)` | what the FX screen's **› OPEN** row and the bottom panel's OPEN button call: `PumpFX.openHook(track, slot, info)` (`info` = `get()`), or, while no hook is set, a toast saying the window comes later. **kit.js sets `PumpFX.openHook`** (a type without a window file still gets the toast). |
| `undo(dir)` | Thunder's undo (−1) or redo (+1): the song's last change, whatever it was (a pop-up's UNDO / REDO and Ctrl/⌘+Z). `onChange` follows with `'undo'`. |
| `toast(msg)`, `trackName(t)` | the app's toast; `'MASTER'` or `'TRACK 04 BUS · name'`. |
| `ownsKey`, `backHook` | hooks the kit sets: `ownsKey(e)` true = the app's key handlers leave this key alone (`typing()` asks it; the kit says yes for keys typed in a pop-up, except Space, which still plays / stops, and Ctrl/⌘ shortcuts the window doesn't use, such as save); `backHook()` true = Back (a phone's back gesture) closed a window. |
| `meta`, `types`, `MASTER`, `key(type)`, `typeOfKey(k)`, `allowed(t)` | |

Undo: Ctrl/⌘+Z replaces the whole song state, so after an `onChange` re-read the slot with `get()`; never keep the slot
object itself.

## Telemetry frames

`cb(frame)`: `{slot, key, type, sr, lat, t, rings}`. `type` is the type index, `sr` the audio thread's sample rate,
`lat` the latency now (samples). Frames come every 12 render quanta (1536 samples, 32 ms at 48 kHz) while sound reaches
the effect; after 1 s of silence at its input the effect node sleeps and frames stop until sound returns.

**`t`** (Float32Array) is the plugin's meters, read once per frame (peak and reduction values are the maximum since the
previous frame, as the plugin's UI exchanges them):

| | all types |
|---|---|
| `t[0]` | latency, samples |
| `t[1]`, `t[2]` | output peak L, R (linear). METER: sample peak L, R |
| `t[3]`, `t[4]` | input peak L, R (linear; COMP, LIMIT, CALM, BAND; −1 where the plugin has no input meter). METER: true peak L, R (linear) |

| type | `t[5]` and on |
|---|---|
| eq (30) | `t[5…28]` each band's dynamic gain offset now (dB, bands 1–24; the plugin's `dynOffset`), `t[29]` auto gain (dB) |
| comp (11) | `t[5]`, `t[6]` gain reduction per processing channel (dB ≤ 0, deepest since the last frame), `t[7]` detector level (dB, input-referred: the transfer curve's dot; −200 = none), `t[8]` external sidechain input peak (linear), `t[9]` makeup now (dB), `t[10]` 1 when Thunder feeds the sidechain (`sck` set: the plugin's "sidechain connected") |
| limit (22) | `t[5]` gain reduction (dB ≥ 0, max), `t[6…12]` output loudness: momentary, short-term, integrated (LUFS), LRA (LU), true peak (dBTP), max momentary, max short-term; `t[13…19]` the same for the input; `t[20]` oversampling factor, `t[21]` gain (dB) |
| calm (448) | `t[5]` broadband reduction (dB ≥ 0, max), `t[6…225]` reduction curve, channel 1 (dB, 220 points: point p at 20 · 1000^((p + 0.5) / 220) Hz), `t[226…445]` channel 2 (right or side), `t[446]` stereo mode (0 linked, 1 L/R, 2 M/S), `t[447]` FFT size |
| tone (247) | `t[5]` makeup (dB), then 48 bands each: `t[6…53]` gain (dB, incl. tilt and auto level), `t[54…101]` target level, `t[102…149]` short-term level (both in the analyzer's dB, pink-flat), `t[150…197]` band frequency (Hz), `t[198…245]` band ERB number, `t[246]` FFT size |
| band (21) | `t[5…8]` each band's dynamic gain (dB, no makeup), `t[9…12]` detector level (dB), `t[13…16]` makeup in use (dB, incl. auto), `t[17…19]` effective crossovers (Hz), `t[20]` bands |
| wide (18) | `t[5…8]` correlation per band (−1…1), `t[9…12]` band level (dB), `t[13]` overall correlation, `t[14]` overall level (dB), `t[15…17]` effective crossovers (Hz) |
| heat (21) | `t[5…8]` level match in use per band (dB), `t[9…12]` band input level (dB RMS, 300 ms), `t[13…16]` band output level, `t[17…19]` effective crossovers (Hz), `t[20]` oversampling factor |
| meter (24) | `t[5]` momentary, `t[6]` short-term, `t[7]` integrated (LUFS), `t[8]` LRA (LU), `t[9]` max momentary, `t[10]` max short-term, `t[11]` true peak max (dBTP), `t[12]` short-term true peak, `t[13]` PLR, `t[14]` PSR, `t[15]`, `t[16]` RMS L, R (dB), `t[17]` correlation, `t[18]` balance (dB), `t[19]` elapsed (s), `t[20]` 1 = silent, `t[21]` reset count, `t[22]` reset high-water, `t[23]` history position at the last reset |

(`-Infinity` / values ≤ −70 mean "nothing measured yet"; LUFS start at −∞.)

**`rings`**: `[{k, pos, d}]`, one per sample feed of the plugin (the `ScopeRing`s its UI reads). `d` (Float32Array) is
the feed's new samples since the previous frame, ending at write position `pos` (`d[d.length − 1]` is sample `pos − 1`;
positions wrap at 2³²). If `pos − previous pos > d.length` some were lost (more than the ring holds). Keep your own ring
of the size you need.

| type | `k` = 0, 1, 2, 3 |
|---|---|
| eq, calm, tone, band, heat | 0 the input, 1 the output, mono `(L + R) / 2`, at the sample rate (32768-sample rings): the pre/post spectrum analyzers (pump's `SpectrumView` takes the newest `analyzerSize(sr)` samples, 8192 at 44.1/48 kHz, doubling per octave of rate up to 32768). EQ's input is before the EQ, its output after the output gain. |
| comp | 0 input level, 1 output level, 2 gain reduction, 3 detector level: dB, **400 points a second** (8192-point rings): the plugin's scrolling history |
| limit | 0 input level, 1 output level (dB), 2 gain reduction (dB ≥ 0), 3 output short-term loudness (LUFS): **200 points a second** (4096-point rings) |
| wide | 0 output L, 1 output R (the vectorscope), 2 mid `(L + R) / 2`, 3 side `(L − R) / 2` (the spectra), at the sample rate |
| meter | 0 the spectrum feed `(L + R) / 2` at the sample rate; 1 momentary, 2 short-term, 3 integrated loudness history (LUFS, **10 points a second**, 32768 points = 54 min; the history since the last reset starts at `t[23]`) |

## Momentary listening: `hold(t, k, kind, a, b, c, d)`

What the plugins do while Alt (or a mouse button) is held. Never saved, never undone; set it back when the key is
released or the window closes.

| kind | |
|---|---|
| 0 | listen to one band: EQ solo band, BAND / WIDE / HEAT listen band. `a` = band index (0-based), −1 = off |
| 1 | audition filter (EQ, CALM, TONE): `a` 1 on / 0 off, `b` frequency (Hz), `c` Q (0.3–12), `d` region (CALM: 0 band, 1 below, 2 above) |
| 2 | LIMIT: reset its loudness meters |

METER's reset is a parameter (as in the plugin): `set(t, k, {reset: get(t, k).values.reset + 1})`.

## Latency

CALM and TONE (STFT: 2048 samples at the defaults), LIMIT (lookahead, true peak, oversampling: about 6 ms at Thunder's
start values), COMP lookahead / oversampling, HEAT oversampling and the linear-phase modes (EQ up to ~0.35 s, BAND /
WIDE / HEAT crossovers ~0.1 s) add latency. Thunder's track FX chain has **no delay compensation**:

- **master**: harmless while playing (everything moves together). **Renders** (mix, stems, Render a part) line it up:
  `pass()` adds the master's pump latency to the mastering's and trims it off the start.
- **a bus**: plays that much later than tracks that don't go through it, live and in renders. The FX screen says so
  (the slot's ACTIVE line, OPEN's help, a note when CALM / TONE / LIMIT go on a bus). Pop-ups should show it too
  (`latency()` or `frame.lat`).

## CPU (pump.wasm, one core of a desktop, 128-sample blocks, 48 kHz)

Measured with node on the test mix (ms of work per second of audio; the worklet itself adds little): EQ 1–5 (linear
phase 10–14), COMP 8–16 (2x/4x oversampling and lookahead ~29), LIMIT 35 at Thunder's start (oversampling off;
2x 45, 8x 76, off without true peak 23), CALM 10–12, TONE 11–16, BAND 12–22 (linear-phase crossovers 23), WIDE 6–8
(linear 23), HEAT 11 at 1x (Thunder's start), 28 at 2x, 43 at 4x (the plugin's default), METER 17. A phone is several
times slower: keep oversampling and linear phase for the master. That's why LIMIT and HEAT start with oversampling off
in Thunder (`PUMP_START`) and presets keep it (`PUMP_CPU`).

## The pop-up kit (`pump/ui/kit.js`, `window.PumpUI`; stage 2)

Each window is one `<canvas>` drawn in the plugin's own **logical coordinates** (EQ 1040 × 660, the others 1000 × 620,
as in `UI<Name>.cpp`), scaled uniformly to the window at the device pixel ratio (at most 2), so a port keeps the
plugin's numbers. The header (brand, tag, kind, preset menu, UNDO / REDO, A / B / COPY, ?, DARK, BYPASS, ✕), the footer
(status line, info, resize grip), typed entry, menus and the help overlay are the kit's, as `PumpUI.hpp` does them.

**Where things open.** Desktop: a window of the plugin's size (fitted to the screen), moved by dragging the header's
empty part (the brand), resized from the corner (uniform scale, remembered per type), several at once (one per slot;
OPEN again raises it). Below 640 css px (a folded phone): the plugin's **narrow layout** (`nW` × `nH`, 480 wide), filling
the screen under the top bar, one window at a time. Esc, ✕ and Back close. Space still plays / stops.

**Light / dark.** `THEME = 'skin'` at the top of kit.js: a dark Thunder skin gets pump's dark palette, a light one the
light palette (`'light'` / `'dark'` there fix it). The DARK key overrides it for every window on this device
(`localStorage thunderplus-pump-theme-v1`); Ctrl/⌘-click DARK follows the skin again. Accents and palettes are
`Theme.hpp`'s, for all nine (`PumpUI.ACCENTS`, `buildTheme(type, dark)`).

**Text sizes.** Use the plugin's NanoVG sizes; the kit converts them (`EM`: Share Tech Mono × 0.887, JetBrains Mono
× 0.758, because NanoVG's size is the ascent-to-descent height) and reads 12 % larger in the narrow layouts.

**Undo.** A gesture is one Thunder undo step: `ui.begin()` … `ui.end()`; inside, `setParam` sends `PumpFX.set(…,
{live:true})` (batched per microtask) and `end()` sends the gesture's values once more without `live`. Outside a
gesture every `setParam` is its own step. Parameters flagged no-undo (64: analyzer, SC listen, unity) go straight out
with `keepPreset`. UNDO / REDO / Ctrl/⌘+Z are Thunder's undo (`PumpFX.undo`). A / B is kept per slot for the session
(switching applies the other setting as one undo step). Your own presets (Save preset… in the menu) are kept on this
device (`localStorage thunderplus-pump-user-presets-v1`, by type); applying one sets `pname` to its name.

### Adding a window

1. `pump/ui/<type>.js`: `PumpUI.define('<type>', {W, H, nW, nH, bypass:true, back:8192, make(ui){ … return hooks; }})`.
   `W`/`H` the plugin's logical size, `nW`/`nH` the narrow layout's (480 × up to ~980 fits a folded Fold), `bypass:false`
   hides BYPASS (METER), `back` = the history the first telemetry frame brings (`subscribe`'s `back`), `cmdKeys` = the
   Ctrl/⌘ letters the window uses itself (EQ `'acvd'`; Z and Y are the kit's; any other Ctrl/⌘ key goes on to Thunder).
2. index.html: `<script src="pump/ui/<type>.js?v=1"></script>` after `kit.js` (the `…PUMP WINDOWS` block); `sw.js`: the
   same path in `FILES` and a new `CACHE`. `electron/copy-app.js` copies all of `pump/` and checks every referenced file.
3. Check headless (desktop and 412 × 915 with touch): open from a bus and the master while playing, drag, type, presets,
   undo, close / reopen, save / reload, no page errors.

telemetry ring by absolute position: `push(ring)`, `at(i)`, `latest(out, n)`, `pos`, `any`), `Spectrum(lo, hi)`
(`SpectrumView`: `setup(sr, N)`, `pointDb(p)`, `pointFreq(p)`; `Spectrum.update(dt, A, feedA[, B, feedB])` runs one or two
analyzers off one complex FFT), `analyzerSize(sr)`, `parseParam(type, spec, text)` (typed entry: 1k, A4, C#3+13, 2x,
50 %, inf, choice names), `open(t, k, info)`, `windows()`, `closeAll()`.

**Telemetry and CPU.** A window subscribes on open and unsubscribes on close (no feed, no repaint once closed). Frames
mark it for repaint; meters and displays repaint at most 25 times a second (`ANIM_MS`), edits and pointer moves at once,
and nothing once the sound has stopped and the meters have fallen. Headless (software rendering, 1600 × 1000, demo song
playing) a window added 90–170 ms of main-thread work per second to Thunder's own ~300 (paint 23–38 ms/s, EQ / METER
spectrum 16 ms/s); a GPU-composited browser spends less.

**Left out for now** (all in the plugins): EQ's per-band copy / paste between instances is per page (works between EQ
windows), the plugins' own undo history is Thunder's undo instead, user presets live on this device instead of
in files, the plugins' "remember DARK for new instances" is this device's setting, COMP's External sidechain is fed by
Thunder's sends and tracks (the menu lists them).

### Multiband windows (`pump/ui/multiband.js`; stage 3)

BAND, WIDE and HEAT call `const mb = PumpUI.Multiband(ui, cfg)` in `make(ui)` after their own controls (as the plugins
call `buildStrip()`), set `mb.disp` (the display `Rect`) in `layout`, draw `mb.drawUnder()` after `screenBox` and
`mb.drawOver()` after their own content, and pass `down drag up hover leave wheel key keyUp help close blur` straight
through (`reload` calls `mb.reload()`). `cfg`:

| | |
|---|---|
| `main(b)`, `second(b)` | the band's symbols for a plain drag / the wheel and for Ctrl/Cmd + drag (BAND threshold / ratio, WIDE width / stereoize, HEAT drive / band mix) |
| `mainName`, `secondName` | their names in the status line and help |
| `fields` | the band's own parameter names (`b1_<field>`): what the band menu copies, pastes and resets |
| `stripValue(b)` | the text at the right of the band's strip (BAND its gain now, WIDE its width, HEAT its drive) |
| `onSelect(b)` | the selected band changed (rebind the band panel) |
| `mainFromDrag(b, start, up)`, `secondFromDrag(…)`, `mainWheel(b, v, dir, fine)` | the value from the drag's start value and its upward travel (px, Shift already applied); defaults: 0.004 of the control curve per px |
| `regionGrab(b, x, y, mods)` → true, `regionGrabDrag(x, y, mods)`, `regionGrabEnd()` | a plugin's own grab inside a band (BAND's GAIN lane = makeup, WIDE's mono-bass line) |
| `help` | extra `[[keys, what], …]` for the ? overlay |

`mb` has `sel`, `select(b)` (keeps the FX screen's BAND in step: `PumpFX.setSel`), `numBands()`, `effXo()` (the
crossovers actually used: Multiband.hpp's `effectiveCrossovers`), `xOf(f)` / `fOf(x)` (15 Hz … 22 kHz), `regionX(b)`,
`regionAt(x)`, `xoverTab(k)`, `bandName(b)`, `bandRange(b)`, `bandMag(nb, e, k, f, sr)` (the LR4 band magnitudes, for the
combined response), `flag(b, 0|1|2)` (solo / mute / bypass), `exclusive(b, t)`, `panelFlags(solo, mute, bypass)` (the band
panel's SOLO / MUTE / BYPASS keys: momentary when held, Ctrl/Cmd-click = only this band), `listening()`, `stopListening()`,
`LO`, `HI`, `STRIP`. Alt + hold a band is `PumpFX.hold(…, 0, band)` (−1 on release, blur and close); the S / M / B
parameters are the plugin's (solo is no-undo, so never a preset change). Esc clears every solo; with none set it closes
the window. Copied band settings are kept per plugin type for the page.

### What stage 3's windows do

- **CALM** (1000 × 620; narrow 480 × 950): input / output spectra, the live reduction hanging from the top (two detectors
  in L/R and M/S, with their legend), the sensitivity curve with its six nodes (drag = frequency + sensitivity, Ctrl/Cmd
  drag or wheel = width, Ctrl/Cmd wheel = sensitivity, double-click = typed frequency → sensitivity → Q, right-click
  menus for a node, a focus edge and the display), the focus range edges, Alt + hold / drag = listen (`hold` kind 1, region
  0, wheel = width), Alt + hold a node = solo its band (region below / band / above for the shelves and bells), DELTA
  (latch or hold; D), H = Soft / Hard, ←/→ / ↑↓ / Delete on the selected node, the reduction meter, GR scale menu.
- **TONE** (1000 × 620; narrow 480 × 886): spectra, the balance curve (boosts neon, cuts in the second colour) without the
  auto level, which is drawn as its own dashed line, the target curve (T hides it), hover readout, Alt + hold / drag =
  listen (kind 1), DELTA (latch or hold; D), A = auto level, the curve scale menu (button or right-click).
- **BAND** (1000 × 640; narrow 480 × 940): the multiband display with each band's action zone, threshold line (drag /
  wheel / type), detector bar and mode / ratio tag, the GAIN lane with the live combined response (drag in it = the
  band's makeup; GAIN ± key 6 / 12 / 24 / 48 dB), output meters, the band panel (mode, seven dials, SOLO / MUTE / BYPASS,
  gain bar, transfer curve with the live dot) and the globals.
- **WIDE** (1000 × 620; narrow 480 × 974): mid / side spectra, each band's width bar from the 100 % line with its
  stereoize hatch, the mono-bass shading and its draggable dashed line, the polar vectorscope with phosphor persistence
  (rings 0 / 1; the image is 1× or 2× the scope's size, whichever is nearer the screen's pixels, so a desktop paints a
  quarter of the pixels), correlation overall (with the lowest of the last 2 s) and per band, the band image diagram.
- **HEAT** (1000 × 620; narrow 480 × 916): input / output spectra, each band's glow (how hard it drives its curve), drive
  bar with curve name and band mix, the band panel (six curves, drive, band mix, level, into-curve readout and heat bar,
  auto gain in use, transfer curve with the band's level), oversampling, auto gain, crossover, mix, output, latency.

Display settings the plugins keep in their own UI state are kept on this device: BAND's GAIN range
(`thunderplus-pump-band-lane-v1`), CALM's GR scale and listen width (`…-calm-gr-v1`, `…-calm-lq-v1`), TONE's curve scale,
target on/off and listen width (`…-tone-range-v1`, `…-tone-target-v1`, `…-tone-lq-v1`); the selected band is the slot's
`sel` (saved with the song). No new telemetry was needed: everything is in the tables above.
