## The surprising finding (for the lead and the owner): the intended bit-exactness is not reached in the wasm
Expected: with the FIR summed in four named accumulators (8d95efc) the strict native build and the fast-math wasm agree, so TUBE / `x_two_hosts_same` go exact. Measured the opposite way round: the new strict native is bit-exact against the OLD wasm in TUBE (and x_two_hosts_same, v_hot), i.e. the old fast-math wasm's lane order IS what `dot4` spells out; but the NEW wasm (built from `dot4` under `-O3 -ffast-math -msimd128`) no longer matches it: fast-math still lets clang unroll / reassociate the four chains. Scratch proof (`dot4` compiled alone with wasi-sdk 25, same flags, 4000 random lengths and data, compared to the strict order in JS): the old single-accumulator loop equals `(a0+a1)+(a2+a3)` in 100 % of the n-multiple-of-4 cases (4000 / 4000); `dot4` compiled the same way matches it in about 54 %; `dot4` with `_Pragma("clang fp reassociate(off)")` at the top of the function matches in 4000 / 4000. **Suggestion to the owner (pump, not mine to change):** put `#pragma clang fp reassociate(off)` (or `__attribute__` / a per-TU `-fno-associative-math` for Oversampler users) in `dot4`; then the web wasm == native strict for the oversampled types and the TUBE rule and the `kRules` entry could go. Until then nothing is tightened. Net effect of 8d95efc natively: the old wasm now agrees MORE (44 / 80 exact, 378 / 533 synth), the new wasm exactly as before (40 / 80, 296 / 533).

## FREEZE creation cost (24a24e1, spectra made at `psyn_new`)
Measured natively (GCC 13, -O2 test program calling `PumpSynth::make(11, 48000)`, machine loaded by another compile): the FIRST make in a process 640 ms; later instances 0.1 ms (the spectra are a process-wide static, not per instance, so the web's "970 ms per instance" is per wasm instance there, per process here). `make` runs on the control thread (it allocates; "creation must stay off the audio thread" holds: `PumpSynth::make` / `builtins()` are control-thread calls). Condition for the wiring (U33 / U34): the first FREEZE `make` must be on a control or loader thread, never in a render callback; `PumpSynth::builtins()` is now redundant (it still works, it just makes FREEZE instances) and is kept. The static's first-use initialisation is thread-safe in C++11 but blocks a second thread that makes a FREEZE at the same moment.
