## Decisions made without asking (contract-keeping)
- One miniaudio device per engine; the live engine has its own device and its own A5 logger (`nativeRtSnapshot` on `LiveNative`); the N0 core and the live host never run together (Kotlin stops one first).
- vars = NULL in `song_publish` (as `test_live_capi`): the page's TFX flags are not available without the page. The song plays with the core's built-in tables.
- The pads are rendered on the caller's thread (not control, not audio) and only the publish runs on the control thread.
- `F_MIDI` is on as asked but no ports are wired (H2): the MIDI outbox is never drained in H1a. If the ring fills, records are dropped and counted by the core (not verified with a long run: owner test item).
- The notification's Stop is the TRANSPORT stop (the service stays until "Quit native"); the N0 engine's Stop still ends the service.
- Host output latency given to `host_stats` is the AAudio buffer size (an upper bound, GUESS); H1c reads the timestamp.
- LEAD'S RULINGS (24 Nov night): (1) the page-side client is a separate designer's (`docs/port/N2-PAGE-CLIENT.md`); the shell follows CORE-BRIDGE v1. (2) An unported pad effect is SONG-level: `SongFit` (H1b) marks the song not playable natively and the shell falls back to the old engine with a message; H1a's dry-with-a-note stays only in the button "Play bundled song natively (test path)". ## Lead's read of 25 Nov: fixes
Step 0: `origin/native` (C2b #311 etc.) merged into `n1/n2-live-shell` with no conflict; the pad effects spring / crush are now ported, so `test_android_live_engine` expects `dry == 0` (was 2).
- **A (HIGH) `nativeStatus`**: miniaudio re-routes an AAudio stream by itself (`ma_job_process__device__aaudio_reroute` closes and reopens it under `pDevice->aaudio.rerouteLock` on miniaudio's own thread). Every read of `g.device.aaudio.pStreamPlayback` and every AAudio call on it now also holds `ma_mutex_lock(&g.device.aaudio.rerouteLock)`, taken AFTER `g_dev` and only while `g.deviceInit`, released before returning. (`ma_device_uninit` takes the same lock, under `g_dev` too: same order, no cycle.) The audio callback must NOT take it (the reroute job holds it while it closes the stream, and the close waits for the callback): see the h2 note.
- **B (MED) `LiveEngine::call`**: `Task::started` (under `t->m`, set by the control thread before `fn`). A wait that times out returns -1000 when the task had not started (dropped, never runs) and -1001 when it was already running (UNKNOWN: it may still apply). Documented in `live_engine.h`; host test in `test_android_live_engine.cpp`.
- **C (LOW) `g.lastSlots`**: after a load with rc != 0 (incl. -1000 / -1001) it becomes the UNION of the old list and the new slots; only rc == 0 replaces it.
- **D (LOW) retry safety**: `RenderedPad::kitDone`; a pad whose `pad_take` worked but whose `pad_kit` did not gets its kit on the retry (the lambda skips only pads with `kitDone`); a taken pad (`block == nullptr`) is never taken again.
- **E (LOW) `pollLoop`**: every record is checked `h.bytes >= sizeof(record)` before its `memcpy` (else skipped by `bytes`), and `off + bytes > n` is computed in 64 bit.
- **F (LOW) `nativeStart`**: `dlopen` / `dlsym` of `aaLib / aaXrun / aaBuf` run under `g_dev`; the `-3` failure path nulls `aaXrun` / `aaBuf`; `nativeShutdown` clears them under `g_dev` too.
