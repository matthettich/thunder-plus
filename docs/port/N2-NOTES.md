**Where:** pure decisions `LivePolicy.kt` (FocusPolicy, StreamWatch, SongTitle, GateRule / GateState); Android calls `LiveSession.kt` (focus, noisy receiver, device callback, MediaSession, 500 ms ticker); `ThunderService.postLive` (media-style notification); native `nativeReopenStream`, `nativeStreamState`, `nativeSetDuck` + `LiveEngine::setDuck` (live_jni.cpp, live_engine.cpp).

**Decisions (each is one constant or one branch; the owner can change it):**
1. LOSS (another app took the audio): stop the transport, give the focus up, no automatic return (as ruled).
2. LOSS_TRANSIENT (a call, a navigation voice): stop, remember the row, resume with `play {row}` when GAIN comes (`FocusPolicy.RESUME_AFTER_TRANSIENT`; false makes it behave like LOSS). A press of Stop / Play by the user cancels the remembered resume. GUESS: a stopped song restarting by itself after a call is what a music app does; the owner may prefer not.
3. LOSS_TRANSIENT_CAN_DUCK (notification sound, navigation prompt): the SHELL's own output gain goes to 0.25 (-12 dB, `FocusPolicy.DUCK_GAIN`) in 150 ms, back to 1 on GAIN. It is applied in the audio callback AFTER the core's master and safety limiter, so the page's master volume (`mix_set` MASTER VOL) is never overwritten. The request sets `setWillPauseWhenDucked(false)` so the system does not duck for us.
4. Play asks for the focus first; a refused request (a call in progress) means no play and an `err` event / `play` rc -3. The focus is given up 3 s after the song is neither playing nor waiting to resume.
5. Headphones unplugged / Bluetooth sink dropped (`ACTION_AUDIO_BECOMING_NOISY`): stop the transport (stays stopped), event `{t:'device', reason:'noisy', stopped:true}`.
6. Output device added / removed: nothing is rebuilt as long as the stream keeps calling back (Android re-routes a default-routed AAudio stream by itself: UNVERIFIED). A watchdog (`StreamWatch`, 1 s without a new audio callback) rebuilds the STREAM only: `nativeReopenStream` stops the transport, closes the stream, opens a new one, keeps the host. Not restarted (a defined state: stopped); event `{t:'device', reason:'stream', stopped:true, sr}`. If no stream can be opened the host ends too and the shell sends `{t:'engine', up:false}` (CORE-BRIDGE 7 G13: the page re-sends song, kit and pads when it sees `up:true`).
7. **A new sample rate: what it needs, and the safe choice.** The host's rate is fixed at `thunder_live_create`; the pads are stored at it; a different rate would need: stop, destroy, create at the new rate, re-render or re-take every pad (1 to 3 s, GUESS), re-publish song and kit, and the page's own `put` pads re-sent. SAFE OPTION CHOSEN: never change the host's rate. The new stream is opened AT THE ENGINE'S RATE and Android's mixer (or miniaudio's converter) resamples to the device; the cost is one rate conversion (a little latency and CPU, UNVERIFIED on a device) and the benefit is that nothing is rebuilt and no state is lost. A full rebuild is still what `engine.reset` does, if the owner wants the exact device rate.
8. The re-anchor: `process` takes the new `frame0`, and the engine keeps its gapless count (live.h TIME paragraph); `LiveEngine::render` keeps counting across the stream change. The A5 logger is NOT reset by a stream rebuild, so a rebuild during the gate shows as a gap and the gate is marked ABORTED (not a pass).
9. Pause is Stop: a song is not resumable from the middle in a useful way (the media session offers Play / Pause / Stop, Pause stops).
10. **Media session and notification.** `android.media.session.MediaSession` "ThunderPlus", Notification.MediaStyle with the session token, actions Play and Stop (compact view both). Title = `SongTitle.pick(title, name, file)`: the `title` member of `song.load` when the page sends one, else the song's `name` unless it is the default ("Song", "Song N": the page's `songNameDefault` rule), else the loaded file's name without `.thunder` (the bundled test song says "ELECTRO"), else "Thunder Plus". Artist "Thunder Plus". Icon: the status-bar icon is a bolt vector (`res/drawable/ic_stat_thunder.xml`); the large icon and the album art are the app's own `icons/plus-icon-512.png` from the APK's assets; the launcher icon is `plus-icon-192.png` (`res/drawable-nodpi/ic_launcher.png`, a copy). No Chrome badge: the notification belongs to the shell, not the WebView.

H1c adds the gate: button "A5 gate 10 min (native)" resets the logger, plays the song (again when it ends, so the 10 minutes are not silence) and judges after 600 s of AUDIO frames (screen state cannot stretch it): PASS = ratio 1.0000 +- 0.001, 0 underruns, 0 late callbacks (`rtlog.h`, unchanged).
