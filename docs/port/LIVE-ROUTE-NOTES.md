So "voices still sounding" does not exist for live engines in the JS (see rule R-L30 and the contradictions in part 2).
* **The core and the page are two implementations of the same protocol** and the page's AudioParam spec behaviour differs from the core's `Auto` in a few places (table D, item 4).

### 2b. Gate / trig / leg to notes

The page and the core write `leg.set(leg,t); gate.set(1,t); trig.set(++n,t)` at a note (`cp:732`, `ix:21806`) after `cancel(t)` on gate / trig / leg (`cp:723`) and `R.hold(t)` on rate (`cp:724`). The node decodes them per sample:
* **bass** (`ix:22633-22638`): `tg !== lt && ga -> c.on(leg[i] >= 0.5)`; `else if (ga && !lg) c.on(false)`; `else if (!ga && lg) c.off()`; before each the segment `[s, i)` is rendered at `rate[s]`. After the loop `c.render(L,R,s,n,rate[s])`. `c.bpm = P.bpm[0]; c.wob = P.wob[0]` once per quantum (`ix:22627`).
* **vox** (`ix:22717-22721`): `c.on(leg>=0.5, Math.round(syl[i]), same>=0.5)` for a new `trig`; `c.on(false, Math.round(syl[i]), false)` when the gate rises with the same `trig`; `c.off()` on a falling gate.
* **acid / mach** (`ix:22797-22801`): `c.on(leg>=0.5, acc>=0.5)`, `c.on(false, acc>=0.5)`, `c.off()`. (`MachCore.on` takes `leg` only; the `acc` argument is ignored by it in the C++ port, `xeng_live.h:35`.)
* **pump synth** (`psw:173-192`), per lane, MIDI with a sample offset `i` into `X.psyn_midi(h, i, status, d1, d2)`: new note when `(tg !== ln.lt && ga) || (ga && !ln.lg)`; `note = clamp(nb + round(tune + 12 log2 r), 0, 127)` (`semis`, `psw:130`); `vel = clamp(round(v), 1, 127)`; **legato only if the lane's gate was already high**: `leg = tg !== lt && ln.lg && l >= 0.5` (`psw:182`); non-legato: note-off of the old note first (`0x80`), then bend, then note-on; legato: bend, note-on, THEN note-off of the old note when the notes differ; falling gate: note-off. Bend: one per instrument (a MIDI pitch bend is per instance: a chord bends together, from the LAST-played lane's rate, `psw:193-200`), `bendOf(r, note) = 8192 + clamp((nb + semis(r) - note)/range, -1, 1) * 8191` with `range` 24 (COIL 12, kits 24, ORBIT / FOLD / TRACT 2, `pse:229-230`), sent every 32 samples when the lane's rate is an array (`psw:196`), once per block for a constant rate, COIL one per block and only when it moved more than 6. Sleep: no held lane, no new note, 1 s of output below 2e-5 -> the engine is not run (`psw:201-203`). Output `(L,R) * trim * 10^(level/20)`, optional `tanh` drive (`psw:210-214`).
* **waves** (`wvw:5960-6000`): per block, "the first change in it counts": a new note calls `V.on(pt, vel)` at the BLOCK'S START whatever the sample was (`wvw:5980`), `pt = 36 + tune + 12 log2 r - 60`, `vel = clamp(v,1,127)/127`; legato only if `leg >= 0.5 && ln.row >= 0 && V.rows[ln.row].gate` (the lane still holds a gated voice) then only `rw.pitch = pt`; a held voice's pitch follows the lane's rate at the LAST sample of the block (`wvw:5989`). Output `soft()` of the bus times level / drive (`wvw:5994-5999`). Sleep after 2 s quiet (`wvw:5992`).

### 2c. Where `ov.g` and `ov.pn` act (`tcOver`, `tcParam`, `tcNodes`, `ov.post`)

* `tcNodes()` (`cp:155`) is the registry of live nodes in the audio-thread scope (each node registers itself by `cid`). `tcOver(proc)` (`cp:156`) makes `proc.__ov = {p:Map of Auto per param, buf:Float32Array per param, g:Auto(1), pn:Auto(0), until:Infinity}`. `tcParam(ov, k, t)` (`cp:285`) makes one `Auto(0)` per param name with `A.from = t`: before `from` the node reads the page's own AudioParam value.
* `__tcOv` (`cp:157-175`) is called at the top of each node's `process`: for each declared param `k` with an override, `A.prune`; if constant over the block the value is a one-number array (`a1[0] = constFrom != null ? c : Math.fround(c)`, `cp:168`), else the Auto is filled per sample into a **Float32Array** (`cp:171`): **the node's lanes are float32 in the non-constant case and double in the constant case**; the C++ shell reads `rate` as double. Difference ~1e-7 relative in pitch: inaudible, but it means "bit-for-bit against the node" cannot hold (gate (b) is against `seqRender`, not the node).
* `ov.post = true` is set by `liveStart` at the first note (`cp:720`); `__tcPost` (`cp:176-195`) multiplies the node's 2-channel output by `ov.g.at(t)` (**gain first**) and then applies the StereoPanner law for a **stereo** input with `ov.pn.at(t)`: for `p <= 0`: `x = (p+1)*PI/2; L = l + r*cos(x); R = r*sin(x)`; for `p > 0`: `x = p*PI/2; L = l*cos(x); R = r + l*sin(x)` (`cp:190-191`; the still-gain-and-pan fast path `cp:182-183` is the same arithmetic). **This is the stereo balance law (cross-feed), not the sampler's mono equal-power `(pan+1)*PI/4` (`cp:808`, `cp:832`).** Is the node mono or stereo: STEREO (2 channels). The engines decide whether L differs from R (bass: yes, per-partial pan `panL_ / panR_`; vox: `L = R`; the rest: see their `render`). A mono-output node (`R` missing) takes `L[i] = l` only (`cp:187`), which never happens for these five.
* `ov.g` and `ov.pn` are **per node, not per voice**: `liveStart` `ov.g.set(gain, t)`, `ov.pn.set(clamp((ev.pan-128)/127,-1,1), t)` at the note's time (`cp:733`), and the voice's `v.g` / `v.pn` ARE these same Auto objects (`cp:736`), so a `mod` gain / pan (`cp:550-551`) moves the node's whole output including the previous note's release tail. They are a step at the note's sample (Auto is read per sample: no 128-quantum). For a poly vox each of the 4 nodes has its own `ov`; for a pump / waves node the four lanes share one `ov`.
* `ov.until` (`cp:157-159`): `Infinity` while the core plays; `stopAll` sets `at + 4`, after which `proc.__ov = null` and the page's own params return. Not meaningful natively (the pool IS the player, L1).
* `ev.gain` for a pump / waves note with a VOL column (`vc >= 0`): velocity lane 127 and `gain = c > 1e-4 ? ev.gain / c : 0` with `c = curve(vc) = (clamp(vc,0,255)/255)^2` (`cp:729-730`, `curve` = `core/seq-core.js:81`, `ix:17984`); without it the velocity is `clamp(round(hit * (ev.vel ?? 1)), 1, 127)` with `hit = lk.vel || 100`.

**`eng` and `engPut`** (`cp:386-399`, `ENG_C / ENG_O / ENG_DEF` `cp:283-284`). The **twelve ENGINE TARGETS** = `cCut cRes cDec cAtk cRel` (-1 = none; from `ev.c.{cut,res,dec,atk,rel}`) and `oCut oRes oEnv oAtk oDec oSus oRel` (signed offsets, from `ev.o.{cut,res,env,atk,dec,sus,rel}`). `ENG_DEF`: the five `c*` -> -1, the seven `o*` -> 0. `engEv`: `at = max(ev.t, currentTime)`; `st = {c, o}`; `def` = all `c < 0` and all `o` falsy; `this.engSt[track] = def ? null : st`; for each live node of the track (`engL[t]`, filled by `lnode`, `cp:687`): `if (def && !L.engOn) continue; engPut(L, st, at, true)`. `engPut`: `ov.until = Infinity`; `rp = ramp && L.engOn`; each finite `c` -> `tcParam(...).set(v, at)`; each finite `o` -> `A.lin(v, at)` if `rp` else `A.set(v, at)`; `L.engOn = true`. A note also does `if (engSt[track]) engPut(L, es, t, false)` (`cp:731`): the state in force is STEPPED in at each note. The node reads them k-rate (`P.cCut[0]` etc., once per quantum: the value at the quantum's first sample, a ramp sampled there) and `engOn(P)` swaps the effective values into the core's parameter object `this.c.p` for that quantum and restores them after (`ix:22597-22621`, `engOff` `ix:22622`). Formulas (identical in the three processors; the target tables differ, section 1): `CI = [0,1,-1,3,2,-1,4]` maps target k to its command (`cut, res, -, atk, dec, -, rel`); for target k with command `c` (the `c*` value or -1) and offset `o`: skip if `c < 0 && o === 0`; k = 0 and no 4th table entry: `clamp((c<0 ? own : 30*K^(c/255)) * K^(o/255), lo, hi)`, `K = 18000/30`; k = 0 with 4th entry (vox `bright`), k = 1, k = 5: `lo + clamp((c<0 ? (own-lo)/(hi-lo) : c/255) + o/255, 0, 1)*(hi-lo)`; k = 2: `clamp(own + o/255*(hi-lo), lo, hi)`; k = 3, 4, 6 (times, ms): `base = c<0 ? own/1000 : 0.008*D^(min(c,254)/254)`, `D = 4/0.008`; `clamp(base * D^(o/254), lo/1000, hi/1000)*1000`. The pump synth does the same in `modRead` (`psw:100-129`) with its `TMAP` ranges and ONE commit of the staged values per quantum when something moved (`psw:163-171`, `COMMIT_EVERY = 1`, `psw:33`). Waves: none. The sequencer sends `eng` for every track with a command, LFO or scene value (`core/seq-core.js:502-520`); a pad that is not live ignores it (`cp:650` returns false; `engL[t]` empty).
**`chc`** (`cp:635-640`): sets a param on the `chn:<track>` node = the chains module's BYP switches (`b1..b15`); it is NOT a live-engine event, nothing in LivePool.
**`tempo`** (`cp:641-643`): the core does NOT set the live nodes' `bpm`: it returns false and the PAGE's `tempoTo` does (`ix:21886-21889`: `b.bpm.setValueAtTime(ev.bpm, max(ev.t, currentTime))` on every node that has a `bpm` param, i.e. bass and the pump / waves nodes; a node made later starts at `bpmNow`, `ix:21692`). **A native `LivePool` must forward `SEV_TEMPO` (today counted in `eventsIgnored`).**
**`stopAll(at)`** (`cp:665-679`, live part): `for L of lnodes: kill(L.cur, at); for lanes: kill(q.cur, at); L.sylN = 0; L.engOn = false;` then for each override param: `gate / g<j>` -> `cancel(at); set(0, at)`, `trig / t<j>` -> `cancel(at)`, each `ENG_DEF` key -> `cancel(at); set(default, at)`, `ov.until = at + 4`; `voxG.clear(); engSt.fill(null)`; every T emptied.
**`sameCol`** (`cp:717`): `ev.col == null ? null : nodes.find(b => b.cur && !b.cur.ended && (b.cur.stopAt == null || b.cur.stopAt > ev.t - 1e-6) && b.cur.col === ev.col && b.lastOn < ev.t - 0.004) || null` (first match in node order).
**`voxG` and syllables.** Mono vox: the node's own `L.sylN`: `kk = fk != null ? fk : leg ? max(0, L.sylN-1) : L.sylN++` (`cp:726`), `leg = slide.dur > 0`, `same = leg`. Poly vox: `voxG[track:pad] = {sylN, lastT: -9, lastK}` (`cp:698`): notes within 4 ms of `lastT` (a chord) share `lastK`; else `kk = leg ? max(0, G.sylN-1) : G.sylN++; lastT = ev.t; lastK = kk` (`cp:700`); `kk` is computed BEFORE the pick, and counts even when the note is then dropped by the `pick.lastOn >= ev.t - 1e-6 && |pick.lastOn - ev.t| < 0.004 && free.length === 0` guard (`cp:702`, "more notes than singers at once": returns true, nothing sounds, nothing is taken over); `voxG` and every `L.sylN` are reset only by `stopAll` (`cp:666-667, 670`). The core's `on(leg, n, same)` does `n mod count`.

**Node binding** (`lnode`, `cp:681-690`): key `track:pad:kind[:j]` (`j` 1..4 for poly vox, absent for the mono node, so a pad that plays both poly and non-poly notes has FIVE vox nodes on that track); a node exists only if the page made it (`tcNodes().get(key)`), else `lnode` returns null and `liveNote` returns false (then `take(ev)`, `cp:660`). Poly pump / waves: one node, `lanes[0..3]`, each `{lane, n, lastOn, cur}` (`cp:685`); the pick among lanes uses the same `free` / `sameCol` / `reduce(lastOn)` (`cp:708`) with **no "more notes than lanes" guard** (a fifth simultaneous note steals the lane with the smallest `lastOn`, ties to the LOWEST index, `x.lastOn <= y.lastOn ? x : y`).

**Counts (proposed).** bass / acid / mach: one node per track that plays the pad. vox: per track **4 poly nodes and 1 mono node** (the JS makes the mono node as soon as a non-poly note is played, `cp:712`; L2 says "polyVox: POLY": add the mono one). The host passes the tracks that can play the pad as a 33-bit mask (the way SF passes `keys`; 0 = all 33), so the pool allocates `popcount(mask)` nodes (x5 for vox). All 33 tracks (no mask) cost: bass **~1.1 MB** per live pad, acid / mach **~0.45 MB**, vox **~5 MB**. A song with a few live pads on a few tracks is a few hundred KB. With one node per (track, pad) available, "re-bind the node whose voice ended longest ago" (L2) never triggers; it is only the fallback when the mask is smaller than what the song plays (counted `liveNoNode`).

**Idle nodes.** The JS node runs every quantum for ever. A native node may be skipped (zeros) only when its core's block is state-neutral when silent: bass `stage_ == 0` returns zeros before touching anything (`bass_core.cpp:82`), acid / mach likewise (`xeng_live.cpp:45, 115`). **Vox is not proven**: `VoxCore::block` advances `st_` and the plan before it can know it is silent (`vox_core.cpp:309-313`). ## L4 (run ahead by `lat`) with `LiveShell::process` as it is

It can be done with the shell unchanged IF the pool owns the future queue and the shell sees only the call's own events. The shell's clock is the mixer's clock `+ lat`: at the start of mixer quantum `[q0, q0+128)` the pool calls `process(L, R, 128, events)` with events whose absolute sample `T` is in `[q0 + lat, q0 + lat + 128)`, as offset `T - (q0 + lat)`; the 128 returned samples are the engine's samples for `[q0, q0+128)` (the shell reads `lat` behind its clock: `live_shell.h:89-100`, `ringL_[(clock_+j) - latency]`; its `process` drops events with `at >= n` at `live_shell.h:90`). So: a node's first call is preceded by `lat` samples of pre-roll with the events of `[0, lat)`. Everything beyond the horizon waits in the POOL's per-node timeline, because **`process` drops any event with `at >= n` (`dropped_++`) and has no way to hold a future one**: the 256-event queue in the shell only ever holds the events of one 128-chunk. Two things the shell does not have and L2 / L4 need: (1) **a way to start a node at a late clock** (a node bound at frame F cannot be run F samples of silence): add `LiveShell::seek(uint64_t clock)` (sets `clock_ = rendered_ = clock`, ring zero; the ring is indexed by absolute sample so nothing else changes); (2) **`reset()` on the shell and the four cores** (state back to constructor state, parameters kept, no allocation: none exists, `grep reset` over the four headers is empty; `VoxCore::set` allocates, `vox_core.cpp:224`), without which "a binding is an assignment and a core reset" (L2) cannot be done for vox. The alternative that keeps the shell untouched is to bind with a placement-new of a pre-sized shell and `set()`: fine for bass / acid / mach (their constructors do not allocate), not for vox. An event for a time inside the look-ahead (`T < q0 + lat`): the pool applies it at the shell's clock (`q0 + lat`) and counts `liveLate` (L4 as written).

## L5 and `LiveShell::enqueue`

As written (the shell's 256 queue) the rule can hardly trigger: the pool hands the shell one 128-quantum of events per call, and `process` takes `nev` from the caller. **The queue that fills is the pool's own timeline** (up to LEAD = 0.25 s = 12000 samples of events per node: a note with an arpeggio books up to 96 rate pairs, `voice.h:101` `kAutoR = 128`; RET gives 64 notes a row). Proposal: L5 lives in that queue (per node, ~256..512 events, 16 B each), with the rule exactly as the lead wrote it; the shell's `enqueue` changes only to also drop `NoteOff` last (it never drops one) for hosts that use `process` directly. The same rule is JS: `kill` with `at < lastOn - 1e-6` cancels gate / trig at `>= at` and then sets the gate off (`cp:535-536`); and a NoteOn cancels the booked gate / trig / leg / rate events at `>= t` (`cp:723-724`). **These cancels are needed on EVERY note, not only on overflow**, so the pool's timeline needs `cancelFrom(t, mask)`; the shell has none (its `enqueue` only inserts). Whether a NoteOn at the SAME sample as a booked NoteOff keeps the off (U26's rule, goldens exist: 122 sequences include it) or drops it (the JS, page and core, D4): with the cancel in the pool's timeline the pool can do the JS thing and the shell's U26 goldens stand (the shell never sees the cancelled off). Gate (b) then must feed `seqRender` the events AFTER the pool's cancel, or exclude that case.

## Where a ruling does not fit the JS (plainly)

* **C1. L2 "a binding is an assignment and a core reset: no allocation".** No core or shell has a `reset()` (empty grep); `VoxCore::set` allocates; so it needs the new `reset()` (and `seek`) above. Not wrong, but not "no new code".
* **C2. L5 as written does not meet the case.** The shell cannot hold a future event (`process` drops `at >= n`) and cannot cancel; the JS needs a cancel on every NoteOn / kill. The rule belongs to a pool-level timeline.
* **C3. L10(b) cannot hold if the pool follows the JS in D4.** The same-sample off + on is `off(); on()` in the shell / `seqRender`, `on()` alone in the page and core. Pick one; I recommend the JS (cancel in the pool), with the one `seqRender` sequence kept as an expected difference.
* **C4. L6 "`voices()` includes live voices".** In the JS a live voice is never counted (not in `alive`) and never ends (R-L30). Natively `drain()` / the "song over and every voice ended" end condition needs a definition and a release at the song's end, or a held bass note ends the render only at `max_frames` (hit_limit) / `E_LIMIT`. The page's own offline render ends at `max(e.t + pad length / rate)` + tail (`ix:24322-24327`) and cuts, it never releases.
* **C5. L2 counts.** Vox needs 5 nodes a track (4 poly + the mono node), not POLY.
* **C6. L1 lists `chc` nowhere, good, but `tempo` is missing from L1:** live bass / pump / waves nodes get `bpm` from the PAGE's `tempoTo` (`ix:21886`), the core drops it (`cp:641`); natively the pool must take `SEV_TEMPO` or a WOB bass runs at 120 BPM.
* **C7. L1 "bends (`pitchMods`)" hides a rate-event translation and a semantic gap.** The JS books `set` / `lin` points (a `lin` event is the ramp's END); the shell's `RateRamp` is a START with a duration; the shell's lane replaces the current piece (the page's `cancelAndHold`), the core's `Auto.hold` keeps the FROM value (D7). * **C8. L4's "waves 127" is the native `WavesLive`'s own latency (`kLiveLatency = 127`, `waves/waves.h:208`), not the JS's** (the JS has none; its notes land at the block start). * **C9. L4's "a pump synth's own figure" is real but is not in the JS:** the JS live pump synth does not compensate the plugin's 32-sample latency (MONO, GLOSS); the port will land them on the note's sample (0.7 ms earlier than the page).
* **C10. L9 step 1 "bass, vox, acid, mach ... `off / mod / stp / stopAll`".** `stopAll` has no caller in an offline render (the page never calls it there); it is for U37 (L7). Cheap, keep it.

### The idle skip
* **Rule.** A node is not processed when: nothing is booked on it (`ntl == 0`, the shell's queue empty), its voice has ended (`!curLive || done`: the C4 flag, gate off and quiet for 4096 samples or 4 s), its core is idle (bass `stage_ == 0`; acid / mach `stage_ == 0 && env_ == 0`; vox `env_ == 0 && envT_ == 0`), the rate lane is constant from here on, and no tap is set. A node nothing was ever booked on is skipped from its first quantum. A skipped node adds nothing to the mix (its output is exact zeros times the gain / pan stage).
* **Waking.** `book()` (every booked note, off, tempo, wobble event) and `modVoice()` (a `mul` / bend writes the rate lane with nothing booked) call `wake()` first. `wake()` = `LiveShell::fastForward(qEnd + lat)`: the whole control blocks that processing would have run (the block grid keeps its phase), the core's `idleBlocks(nb, rate)` (only vox carries state through idle blocks: the pitch latch `lf_`, the formant / noise controls' smoothing, the vibrato clock, `st_`; it shares `prep()` / `step()` with `block()` so the arithmetic is the same code), the output ring zeroed, the clock set. Run-ahead (`lat`), tempo, eng lanes and the vox syllable counter are pool-level and untouched by idle blocks. Lane pruning is left to the next quantum that runs.
* **Proof (bit for bit).** `test_live_idle`: (1) the shell's contract: for every N in {1 ... 9000} samples, `fastForward(clock + N)` equals processing N samples of silence, all four kinds, a second note at another rate (the vox pitch is still gliding), the next note 1 to 28 samples after the stretch, a tempo event; (2) a skipping pool and a processing pool (`setIdleSkip(false)`) get the same scripts, every quantum of every track compared with `memcmp`, stats and `debugVoxG` compared: 305 pairs over all four kinds: first note after a stretch at 6 + 4 offsets with a rate that differs from the idle one, 60 ring / block alignments, events inside the stretch (tempo, wobble, eng, stopAll), a node that never ran, a slide that outlasts the voice, a hold, the poly nodes and the syllable counter, a node handed its first note at the pool's second quantum, a slow vox glide, a mod on a choked idle node. Each scenario asserts the skip was engaged (`idleNodes() > 0`, 0 in the processing pool). The extended B3 `idleNeutral` in `test_live_reset` stays.
* **Cost (Release, this machine, `test_live_idle --bench`; silent vox pad, 33 tracks = 165 nodes, 20 s):** before (skip off) 4596 ms never played, 4968 ms every track played one note first (0.23 / 0.25 x real time); after (skip on) 4 ms and 214 ms (0.00 / 0.01 x real time). The verifier's 3x real time was on a loaded machine; the ratio is what counts. The 214 ms are the first seconds after the notes, until each voice has ended (`done`).
* **Equivalent mutants removed rather than excused.** Wakes in `startNote`, `kill`, `bookCtl`, `engPut`, `stopAll` and the lanes' prune at wake were redundant (every one is followed by a `book()` or touches lanes idle blocks do not read); they were removed so no mutant of them is equivalent. The plan check in `VoxCore::idle()` was redundant for the same reason (`envT_` is 0 only at a rest or the plan's last segment). The `mod` wake (I08) is the one whose effect did not show in the output of any scenario tried, so `test_live_idle` asserts directly that the event ends the node's skip (`mustWake`).
