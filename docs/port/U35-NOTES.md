## Part 1. The JS

### 1.0 Who sends, and when (the architecture)
- **All MIDI out is sent from the page's main thread.** The audio-thread sequencer (`core/seq-core.js`, `core/core-processor.js`) never sends MIDI. With "Audio thread" on, the core steps the song and posts its rows to the page (`core-processor.js:792` `op:'rows'`); the page's `coreMsg` runs `moEv(e)` for EVERY event of every row (`index.html:23815` `const midiOnly = moEv(e)`), and books clock / LFO / CC glides / echoes from the pump tick `corePump` (`:23839-23843` `moClock(s); moLfo(s); moRamp(); moEcho();`). With "Page", `pump()` does the same from its own step loop (`:23452-23457`). So there is one MIDI scheduler, the code in section "MIDI out and MIDI clock", fed by sequencer events; its input is the same stream in both modes.
- The core does not play a note for an instrument with `mo == 1` (`core-processor.js:657` `(I.mo | 0) === 1) return false`; same in `seq-core.js:1515`). The page player skips it too: `moEv` returns `m === 1` (`:17029`), and the pump / `coreMsg` `continue`s (`:23452` `if (moEv(e)) continue`, `:23816` `if (midiOnly) continue`). `mo == 2` (PAD+MIDI) plays on the pad AND sends. The native counterpart is already there: `render.cpp:36` `S_.insts[ii].mo == 1 -> notesMidiOnly++`.
- The pump runs every 25 ms (`pumpTimer`, `:23223` `pumpW.postMessage(25)`, a Worker timer; a `setInterval(pumpTimed, 25)` fallback). `pump()` runs once at PLAY too (`:23161`). The step loop books up to `ahead = max(0.25, outLat + 0.1)` seconds ahead when the page is visible (`:23450`), 1.2 s when hidden (growing 0.75 s per second); at most 64 steps a tick (256 hidden) (`:23452`). With the core: the core books `LEAD = 0.25` (`core-processor.js:291`, `:780` at most 3 steps a block), the rows arrive in `coreMsg` after that, and a message whose time is already past goes out at once (`:16791` `Math.max(now, at)`).
- The PLAY start: the song's clock starts at `ctx.currentTime + 0.08` (`:23133`, plus count-in and warm-up extras). `moStart(row)` runs before it (`:23120`).
- STOP: `tStop` sets `tp.on = false` first, then calls `moStop` (`:23887` `if (!handing || mx.clk.on) G('MIDI stop', moStop)`). Song end: `frame()` calls `tStop()` once the sequencer is not alive, `tp.q` is empty and `ctx.currentTime > tp.seq.time + 0.3` (`:33678`).
- Other places that send (all through `msend`): live keys (`preview` / `previewOff`, `:24182-24202`; `kbCC` `:16635`, `kbPass` `:16646`, `susUp` `:16645`: MIDI-in thru, boundary item 2), `panic` (`:23849`), the latency measurement `midiLatRun` (`:15741-15752`, UI), `clkPortToggled` / `clkJoin` (`:17672-17682`), the cable-change handler (`:17665-17669`). **Not live MIDI:** the Standard MIDI File export `:24751-24779` (`midCh`) is a separate feature (file, not port) and not U35.

### 1.1 The path: msend, the clock mapping, the outbox, the ledger
- **`msend(bytes, t, early, p)`** `:16787-16794`: one message to port `p` at audio time `t` (null: now); returns silently if the port has no cable (`const o = midiOut(p); if (!o || !ctx) return;` `:16788`; `midiOut` `:16754` is null for an empty letter or an unplugged cable). `at = t == null ? 0 : a2p(t + moFxLat()) - (early ? mLatOf(p) : 0)` (`:16789`). `early` = notes and what goes with them (CC, PGM, bend, AT, echo, LFO); the clock messages and the transport (Start, Continue, SPP, Stop) and `t == null` messages are NOT moved by Gear delay.
- **Timestamp** passed to the port: `Math.max(now, at)` (`:16791`), `performance.now()` ms (a fractional millisecond double). One `o.send(bytes, ts)` per message, an array of 1 to 3 bytes. **No running status, no batching, no SysEx.** A send that throws is swallowed (`catch(e){}` `:16791`; `:16790` for the outbox path).
- **Gear delay** `midi.lats[p]` per port, ms, integer, clamped to -50..200 (`:17695`), applied as `- mLatOf(p)` (`:16480`). Measured by `midiLatRun` (`:15741`) and applied by the panel (`:15831`). Negative = later.
- **Audio clock to performance.now()**: `a2p(t) = t * 1000 + amap.off` (`:16784`), `amap.off` from `getOutputTimestamp()` (`pt - ct * 1000`), smoothed at 2 % per call, a jump over 50 ms taken at once, never sooner than `baseLatency + outputLatency` (`:16768-16782`); `mapUpd()` is called on every `moClock` and every 500 ms from the input timer. It is a shell concern: in the native core the audio clock is a frame count and the shell maps it (Part 3).
- **FX latency** `moFxLat()` `:16801-16808`: every timed message is later by `mstLatency(S.mst) + pumpChainLatency(S.mfx) + safeLatency` (samples, `/ sr`) `+ (pdcModeOf() === 'auto' && !tp.on ? 0 : pdcPlan(sr).T)`: mastering CALM 2560 samples + limiter look-ahead (`mstLatency` `:22906`: `(M.sup.on ? 2560 : 0) + (M.lim.on ? round(sr * look / 1000) : 0)`), the master pump effects, the safety limiter (`safeLatency` `:22377`: `round(sr * 3 / 1000)` = 144 samples = 3 ms at 48 k, ALWAYS present), and the PDC delay `T` while playing. Cached for 250 ms, reset at PLAY and STOP (`moFxAt = -1e9`, `:23158`, `:23880`). Ledger `fx-latency`: mastering + PDC + limiter give +71.6 ms; every other case shows the constant +3 ms.
- **Outbox (browser ports only)** `:16810-16820`: when `!o.native` and `at - now > MOB_AHEAD (60 ms)` and the page is visible, the message waits in a time-sorted queue (stable for equal times, so an OFF stays before the next ON) and `mobFlush` (every 15 ms) sends it with its exact timestamp once within 60 ms. `moRelease` drops the queue (`mobDrop`, only `if (!tp.on)`). Hidden page: sent straight away.
- **Hidden-page ledger (browser only)** `:16826-16843` `MOLED`: every note-on sent ahead while hidden is remembered; `moledCut` (in `moRelease`) sends its note-off 1 ms after its own start, then All Notes Off now and after the last. Web-only, because Web MIDI cannot recall a message; not needed natively (see R-M31).
- **Native helper port** (`o.native`, `:17424-17520`): `send(b, ts)` validates (`nmValid`, `:17487-17502`: status >= 0x80, no SysEx, lengths 1/2/3, data < 0x80; the ledger tool runs the app's own `nmValid` on native ports, so every message here is valid) and queues for `ts` in the helper's sender thread (`io/src/midi.cc`: sleeps to 0.5 ms before, spins the rest; `midiClear(port)` drops what is queued, called from `moRelease` as `o.clear()` `:17181`; ns on the OS clock; a message sent > 2 ms late is counted in `late`). Everything is sent at once with its full look-ahead; STOP's clear is what makes it safe. **This is the model the native core follows**; the shells that have no clear get the web's outbox rule in the core (Part 3).

### 1.2 Notes for `mo` instruments (`moEv` `:17012-17030`, `moNote` `:16926-16971`, `moPlay` `:16908`)
- Instrument fields: `mo` 0 PAD / 1 MIDI / 2 PAD+MIDI (`:16737`), `mch` channel `(I.mch | 0) & 15` (`:16928`), `mpt` port letter `clamp(I.mpt | 0, 0, 3)` (`:16755`), `pbr` bend range `clamp((I.pbr | 0) || 2, 1, 48)` (`:16756`), `mlen` NOTE LEN ticks, `cc[4]` the CC numbers (default `CC_DEF = [74, 71, 1, 7]` `:18007`, `ccNum` `:18009`), `eco ecr ecf ecp` echo, `lcc lsh lrb ldp lct lrg` LFO. (`mrng`, `gtype`, `gcen` are the MUT / GEN range: not MIDI.) The native `Inst` has all of them (`song.h:37-40`).
- **Dispatch** (`moEv`): a `beat` event updates the clock anchor; `off` -> `moOff` / `moOffCols`; `mod` -> `moMod` (a muted track just ends its notes); `mcc mpg mpb mat` -> `moCmd`, returns true (pad never plays them); a `note` with `ii == null` is ignored; `mo == 0` -> `moOff(track, e.t)` (the column switched to a pad instrument ends the gear's note) and returns false (`:17027`); `mo != 0` and the track audible (`e.track >= S.mix.length || audible(e.track)`, `:17028`) -> `moNote`, else `moOff` (muted: gear goes quiet).
- **Note on**: `n = clamp(round(e.mn), 0, 127)`, `fine = e.mn - round(e.mn)` (`:16929`). `e.mn = note + 12 + ntc / 100` (`seq-core.js:705`: tracker C-4 = 48 -> MIDI 60; includes transpose, scale, PIT / FIN, the song's tuning in cents, `ntc`). Note-on bytes `[0x90 | ch, n + arpStep, vel]` at `e.t` (`:16913`).
- **Velocity**: `vel = clamp(round(e.vel * 127), 1, 127)` (`:16932`) with `e.vel = hg * (fx.VOL ?? r[VC] ?? 255) / 255` (`seq-core.js:705`; `hg` = HUMAN VEL factor); linear, the instrument's `vol` and the pad `curve()` are NOT applied. **A note with `e.vel <= 0` (vol 00) sends nothing at all** (`:16927` `if (!((e.vel == null ? 1 : e.vel) > 0)) return;`, before any note-off): see B1.
- **Note-off timing** (`moEnd` `:16845`, `moPlay` `:16908-16920`, `offOne` `:16846`): a note's end is `min(e.cut (KIL), e.rel (OFF command), e.t + I.mlen * e.tick if mlen > 0 && tick > 0)` (`:16931`); the off is booked at once with the on, at `max(t + 0.001, end)` (`:16915`) as `[0x80 | ch, n, 0]` (velocity 0, never `0x90 .. 0`). With no end the note is held (`Infinity`) until: **(mono track)** the next note on the track (`if (!e.poly) moOff(t, e.t)` `:16940`: the off goes at `max(e.t, h.t + 0.001)`, i.e. at the next note's time, BEFORE its on); an OFF note (`off` event, col OFF = 200) -> `moOff` at `e.t`; a muted track; a track switched to a pad instrument; `mod` with KIL / OFF (`:17024` `moEnd(e)` -> `moOff(e.track, end)`); STOP / song end / panic / OUTPUT, PORT, CH change (`moRelease`). **Pattern loop**: nothing special, notes and the clock carry on; a note held over the loop edge is ended by the next event. Ledger: `mono-notes`, `note-len`, `loop`, `song-end`.
- **Poly vs mono**: mono tracks `moOff` the whole track first. Poly (`e.poly`, tracks 8..15 of 16, `polyFrom`): each note column is a voice: a new note in a column ends that column's note (`h.col === e.col`), the same key on the same port and channel is ended first (`:16942`), and past `e.cap || 4` sounding notes the oldest is ended (`:16946`; cap 16 for keys); an `off` event with `cols` ends only those columns' notes (`moOffCols` `:16849`). An ARP's steps are one note (`nid`). Ledger `overlap-poly`. **Several tracks on one port + channel** share MIDI's single note state: a note-off of one ends the other's same key (`chan-share`).
- **Echo** (`:16964-16969`, `moEcho` `:17047`): `eco` repeats, `ecr` beats apart (`dt = ecr * 60 / bpm`, bpm = `tp.seq.bpm`), each `ecf` % softer (`vel * (1 - ecf/100)^k`, stops when < 1), `ecp` semitones higher each, length `max(0.005, min(dt * 0.9, noteLen))`; booked within 100 ms of `ctx.currentTime` by the pump tick; an echo is left out while a real note holds its key and ended 1 ms before a real one (`:17047-17060`). Sequenced notes only (`t < NT`). Ledger `echo`.
- **PGM, CC, MPB, MAT** (`moCmd` `:16995-17011`, sequencer events `seq-core.js:660-666`): only for an instrument with `mo != 0` on an audible track (`:16996`). All go out with `early = true`. `mpg`: `[0xC0 | ch, v & 127]` at `e.t - 0.001` (`:16998`; `v = min(127, PGM)`). `mpb`: 14-bit `b = clamp(round(v * 8192 / 128), 0, 16383)`, `[0xE0 | ch, b & 127, b >> 7]` (`:16999`: `MPB 80` = centre 8192; 0 = bottom). `mat`: channel pressure `[0xD0 | ch, v & 127]` (`:17000`). `mcc`: `[0xB0 | ch, ccNum(I, k), clamp(v, 0, 127)]` (`:17002`; commands CCA..CCD, `v = min(127, v)` in the sequencer); the INS command or the row's instrument picks which instrument (`miOf`, `seq-core.js:660`), so a CC can go to another port and channel (`cc-ins`). **CSL** (`ramp > 0`): a glide from the last value sent on that port / channel / CC (`mx.ccv`, `:17003`; a CC never sent there just jumps) to the new one over `CSL * tick` (CSL 00: the step), a message every `LFO_DT = 0.01` s when the integer value changes (`moRamp` `:17032`, booked 80 ms ahead by the pump, `n < 40` a tick); a new CC value on the same key ends a glide still going (`:17004`). Ledger `cc-program`, `cc-ins`.
- **Pitch bend** (`bendTo` `:16856-16863`): `v = clamp(round(8192 + st / rng * 8192), 0, 16383)`, `[0xE0 | ch, v & 127, v >> 7]`, per port+channel (the whole channel bends). A channel never bent counts as centred and a value equal to the latest one in time is not sent again, so a song with no bend commands sends no bend at all (`:16859-16860`). Sources: a note's own fraction of a semitone (`fine`), **PIT / FIN** (in `e.mn` for a note, `mod.mul` on a held note, `bendTo` at once, `:16977`), **PSL** slide: the note starts at the bend of `12 * log2(from / rate)` (clamped to +-range) and glides to its own pitch over `max(0.001, dur)` (`:16949-16951`, `:16959`), **PBN** a ramp to `12 * log2(mul)` semitones until the row's end (`:16961`), **PVB** a sine wobble at `1 + spd * 1.2` Hz, depth `dep / 15 * 1.5` semitones, `N = clamp(ceil(d * hz * 16), 8, 160)` points then back to centre (`bendVib` `:16874-16878`); ramps are a message about every 10 ms, at most 48 (`bendRamp` `:16868`). One ramp per channel and row (`rampOnce`, `:16866`): a chord shares it. `mx.bend` remembers the last 14-bit value and its time. **Bends are sent; the range is only a scale**: the app never sends the RPN 0 "bend range" message, so the gear must be set to `pbr` by hand (see A5). Ledger `slide-arp`, `bend-fine`.
- **ARP on an `mo` instrument** (`arpSegs` `:16880`, `moPlay` segments): the note's steps are separate note-ons at `[time, round(12 * log2(mul))]` semitones from the note, each ending at the next step, the last at the note's end; steps at or after the end are dropped (`:16882`). While the steps run, the note's return to its own pitch waits (`mx.pend`, `arpBack` `:16887`) until the sequencer has moved past, then plays at that time (`pendAt` / `pendFlush` `:16894-16906`; the pump calls `pendFlush` for tracks a row left alone, `:23454`). ARP on a row with no note (`mod`) re-plays the held notes as steps (`moMod` `:16973-16992`). Ledger `slide-arp`.
- **Muted / solo tracks**: `audible(t)` (`:20669`; a solo elsewhere mutes this one; busses count). A muted track sends no notes, no CC (`moCmd` `:16996`) and its held notes end at once (`:17028`). Ledger `muted-solo`, `cc-program` (track 2).
- **KEYS PLAY / pad taps on an `mo` instrument** go through `preview()` -> `moNote` with `t = p2a(performance.now() + mLatOf(port) + 1)` for a held key (out NOW, `:24191`), poly, cap 16, and `previewOff` -> `offNote(NT, nid, p2a(now + lat + 1))` (`:24201`). Not sequenced: a live note path the core needs (CORE-BRIDGE `note.on/off`). Ledger `panic-keys` (the harness copies these two calls).

### 1.3 MIDI clock out, transport, song position (`moEv` beat `:17013-17020`, `moClock` `:17062`, `moStart` `:17071`, `moStop` `:17191`)
- Goes to each port with its clock box ticked and a cable picked, each CABLE once (two letters on one cable: one stream) (`clkPorts` `:16759-16765`). `clkWanted()` = any port ticked.
- **Anchor**: the sequencer emits a `beat` event on EVERY step (`seq-core.js:466-467` `{type:'beat', t:t0, b:api.bt}`; `bt` = the song position in beats, integrated with the tempo of each step). `moEv` keeps the latest as `mx.beat` (`:17014`).
- **Start**: on the first `beat` with `b === 0` after PLAY (`:17015`): `[0xFA]` at `e.t` (no Gear delay, `:17018`), or, for a PLAY from the middle of a block of song rows (`mx.spp > 0`), `[0xF2, spp & 127, spp >> 7]` at `e.t - 0.05` then `[0xFB]` at `e.t` (`:17017`). `spp` = 16ths from the block's top row, `round(beats * 4)` clamped 0..16383, from a silent run of the same sequencer (`sppFor` `:17112`, `songRowBeats` `:17085-17103`, `songBlockTop` `:17082`: contiguous filled song rows above). A PLAY from a sect / phrase or the top sends Start. `moStart` zeroes `mx.beat, t0, lfo, clk` and works out `spp` (`:17071-17075`). Ledger `start-midway`, every clock case.
- **Ticks** (`moClock`, once per pump tick, after the step loop): 24 per beat, from the latest anchor: `upto = b.b + (min(s.time, currentTime + 0.08) - b.t) * s.bpm / 60`; for `k` while `k / 24 < upto`: `at = b.t + (k / 24 - b.b) * 60 / s.bpm`, `[0xF8]` at `at` (no Gear delay), at most 512 a call (`:17062-17070`). **Ticks are booked 80 ms ahead, not the sequencer's 250 ms**, so a STOP leaves few unrecallable ticks. **Straight: swing moves notes, not the clock** (`tempo-clock` has swing 60 %). The tick time uses the CURRENT `s.bpm` and the latest anchor, which can be AHEAD of the tick: see B2.
- **Tempo changes** (TPO command, tempo box, Link, clock-in): the sequencer's `bpm` changes (`setTempoLive` `:17235` sets `tp.seq.bpm`); ticks follow it from the next booking (above). No message is sent for a tempo change (MIDI has none). Ledger `tempo-clock` (TPO 90 at step 16), `tempo-live` (140 at 2.0 s, 97.5 at 3.0 s).
- **Stop** (`moStop` `:17191-17196`): after `moRelease`, `[0xFC]` to every clock port (or, if none is ticked, to every connected port) at `last + 0.001` (`last` = the last tick BOOKED, if still in the future, else now) (`:17193-17194`); the clock state resets (`mx.clk = {on:false, k:0}`). A song's end ends the same way (`frame()` 0.3 s after the last step). Ledger `start-stop`, `song-end`.
- **STOP -> PLAY** never sends Continue by itself: PLAY calls `moStart(o.row)`, and RESUME (`:23104-23118`) passes the resume row as `o.row`, so a resumed PLAY gets Start (top of a block) or SPP + Continue (a row below the block's top) from `mx.spp`.
- **Port changes while playing** (`:17665-17682`): a clock box ticked mid-song: `[0xF2, pos]` at `now + 0.02` and `[0xFB]` at `now + 0.05` (`clkJoin`: `pos = round((spp/4 + beat + elapsed beats) * 4)`), and ticks continue with a fresh `k = ceil(beats * 24)`; unticked: `[0xFC]` after the last booked tick. A cable change: `moRelease`, `[0xFC]` straight to the old cable (`was.send`, no timestamp), the new cable joins as above. Ledger `clock-port-toggle`.
- **Count-in (REC)**: clicks only; no MIDI beyond the usual.

### 1.4 LFO to CC (`moLfo` `:17154-17175`, `lfoWave` `:17136`)
For each instrument with `lcc >= 0` and `mo != 0`: from `max(L.t + 0.01, currentTime)` to `min(s.time, currentTime + 0.08)` in 10 ms steps (`n < 40`): `v = clamp(round(mid + wave * dep * 64 / 127), 0, 127)` (`dep = ldp` default 64, `mid = lct` default 64), `wave` of SINE / TRIANGLE / SAW UP / SAW DOWN / SQUARE / RANDOM (a hash of `cyc * 7919 + ii * 104729 + round(trigger * 1000)`; deterministic); rate `LFO_RATES[lfoRateI(I)]` beats (`lrb`, nearest of 14); FREE: phase from the song's beat clock since PLAY; NOTE (`lrg`): from the instrument's last note (`lfoTrig`, called from `moNote` `:16935`). Sent only when the value changes, `[0xB0 | ch, lcc, v]` with `early`. Ledger `lfo-cc`.

### 1.5 Stops: what ends everything
- **`moRelease`** (`:17176-17190`; called from STOP via `moStop`, from panic, and from OUTPUT / PORT / MIDI CH edits `:25729-25775`, a cable change, a MIDI-engine switch): drops the outbox and calls the ports' `clear()` (only when `!tp.on`, i.e. a real stop; `:17179-17181`); for every held note still ending in the future: `[0x80 | ch, n, 0]` NOW (`t == null`, no delay) and, if the note had not started yet, again at `h.t + 0.001` (`:17183`, harmless duplicate); for every port+channel ever used (`mx.used`, which is NEVER cleared, see B6): **All Notes Off** `[0xB0 | ch, 123, 0]` now and, if the channel's bend is off centre, `[0xE0 | ch, 0, 64]` (re-centre; `:17185-17186`); echo notes already sounding get an off; `mx.held / pend / bend / ramp / ccr / echo` are emptied (`:17188`, note `mx.ccv` and `mx.used` are not); `susUp()` sends CC 64 = 0 if a key pedal was down (`:16645`). Ledger `start-stop`, `song-end`, `loop`.
- **`panic()`** (F8 when already stopped, `:23849-23855`): `moRelease` then, for every CONNECTED port and all 16 channels: `[0xB0|ch,64,0]`, `[0xB0|ch,120,0]` (All Sound Off), `[0xB0|ch,123,0]` (3 x 16 x ports, in that order). Ledger `panic-keys`.
- **There is no all-notes-off on a muted track**, only the individual note-off (R-M20). There is **no pattern-edge note-off other than the above**; a poly column's OFF note is the only per-column release.
- **Port missing**: `msend` returns silently; `moRelease` / `panic` skip it. Nothing is queued for a cable that comes back later; the Settings line says "not connected" (`:18015`). `midi.access` null (MIDI never connected) is the same.

### 1.6 What is NOT in the web's MIDI out (searched, not found)
- Pitch-bend RANGE (RPN 0) messages: not found (`grep -n "101\|RPN"` in the section: none). Bank select (CC 0 / 32): not found; PGM sends only the program change. Sustain pedal CC 64 only from KEYS PLAY and panic. No SysEx, no MIDI time code, no Song Select, no Active Sensing, no `0xFF` reset. No MIDI-out for the master column or bus tracks (`t < MT`, `seq-core.js:659`). No separate note-off velocity. No "MIDI delay" setting besides the per-port Gear delay and the FX latency.

## Part 1, item 2. MIDI IN: the boundary
Not U35 output scheduling; marked here so nothing is lost.
- **U36 / shell:** receiving bytes and timestamps from the OS (`connectMidi1` `:16676`, `hookInputs` `:16654`, the native helper's `midiIn` batch `:17394`), port lists and choices (`miPorts` `:16661`, `moPorts` `:17656`, `midi.outIds / clk / lats` and their saved settings, `:16478-16500`), Learn (`setLearn` `:16693`), notes in -> pads / keys (`onMidi` `:16528-16600`), CC maps. `kbPass` / `kbCC` (MIDI thru of keys, wheel, aftertouch, CC to the gear) call `msend(.., null, false, p)`: they are live messages for the same sender (R-M32); the choice of "what is thru" is the shell's.

## Part 2. The ledger tool (what it does, so a reader can trust it)
`tools/midi-ledger.mjs` loads `core/seq-core.js` (`makeSeq`, the page's sequencer; `tools/make-core.mjs --check` is run first and must pass) and CUTS the MIDI code out of `index.html` by patterns (16 pieces: the whole section "MIDI out and MIDI clock" `msend` to `moStop`, `clkPortToggled` / `clkJoin`, `panic`, `susUp`, `ccNum`, `CC_DEF`, `mLatOf`, the `midi` settings object, `audible`, `mstLatency`, `safeLatency`, `nmValid`, ...) into one `vm` context. It replaces only the outside world: a virtual `performance.now()` and audio clock (1 ms steps, the pump every 25 ms, the outbox every 15 ms, `frame()` every 17 ms), fake output ports recording `(ts, bytes)`, with `native` ports having `clear()` (drops not-yet-due messages) and validating with the app's own `nmValid`. A few page functions are COPIED into the harness (the pump's step loop and bookings, `tStart` / `tStop`'s MIDI lines, the song-end check, the cable handler, the live-key calls); the tool checks that each copied line still exists in `index.html` verbatim and stops with its name if not (a pattern that does not match stops the tool: no silent empty ledger; every case also asserts it saw its notes / clock / CC / PGM / bends).
- 28 ledgers: 24 cases on a native port + 4 of them also on a browser port (`-web`), plus `midi-ledger-index.json` (counts, bytes, sha256). Sizes (messages): `mono-notes` 15, `note-len` 11, `overlap-poly` 27, `chan-share` 7, `two-ports` 101, `velocity` 17, `tempo-clock` 219, `tempo-live` 149, `start-stop` 74 (+`-web` 76), `song-end` 49 (+`-web`), `start-midway` 158, `clock-port-toggle` 186 (+`-web`), `loop` 271, `cc-program` 35, `cc-ins` 7, `slide-arp` 72, `bend-fine` 22, `modes-mixed` 6, `column-switch` 5, `echo` 17, `lfo-cc` 172, `fx-latency` 35, `muted-solo` 5, `panic-keys` 55 (+`-web`). Total about 170 KB.
- A ledger file: `case`, `mode`, `why`, `setup` (everything the C++ test must set up: song spec, ports, clock, Gear delay, output latency, PDC, actions), `seqEvents` (counts of each event type the sequencer produced: cross-check for the native `Seq`), `counts`, `droppedByClear`, `drops`, `pad` (the note events the pad would have played: shows `mo == 1` suppression), `findings` (the replay of what the gear is left doing), `msgs`: `{ms, sent, p, id, k, b}` in the order the port was handed them. **`ms` = the timestamp given to `send()` minus 1000**, which with the harness's mapping is `1000 * audioTime + 1000 * outputLatency` (the case `fx-latency` has 0.02 s). `sent` is the virtual wall time of the `send()` call: informational (it shows the look-ahead: notes ~230 ms, clock 80 ms, LFO / CSL ~80 ms).
- The songs are ELECTRO's song object with its grid, phrases and mastering cleared and a small spec filled in (`mkSong`); BPM 120, LPB 4, ticks 6 (a step is 125 ms, a tick 20.83 ms); every song ends with an END command after one pass unless the case says otherwise. Tracker note 48 = MIDI 60.
- **Determinism proof:** `node tools/midi-ledger.mjs --out /tmp/a; node tools/midi-ledger.mjs --out /tmp/b; diff -r /tmp/a /tmp/b` prints nothing; `sha256sum *.json | sha256sum` is `57b02cb664ed...` in both. Nothing reads wall time, `Math.random` or the environment; ports and timers are virtual.

## Part 3. Proposals for the lead

### 3.1 Shape
- **Where:** `native/core/src/midi/midisched.{h,cpp}`, class `MidiSched`, one instance per live core, owned by the same object that owns `Players` / the `SeqRunner` (LIVE-ROUTE). It is NOT in `Players`: MIDI has no voices; it only needs the events.
- **What it is called with (audio thread, no allocation, no locks):** (1) `onStep(const SeqEvent* evs, int n, const SeqStep& step)`: the lambda `SeqRunner::pump` already takes (one call per played step, in order), the exact analogue of the pump's `for (e of r.evs) moEv(e)` + `pendFlush`. (2) `book(double now, const Seq& seq)`: once per audio block after the pump, = `moClock; moLfo; moRamp; moEcho`. (3) `start(row, ...)` / `stop()` from the control messages PLAY / STOP (the host publishes the SPP, computed on the control thread with a `sim` Seq as `sppFor` does; the host also hands the FX latency in frames, from `Mixer` / `FxHost` latency, re-read when the plan changes). (4) `live(port, bytes, ...)` and `noteOn/noteOff` for keys, `panic()`.
- **State is fixed-size:** held notes per track (an ARP can book 96 segments: cap 128 per track, counted and dropped past it, like the sequencer's `dropped`), `bend[4][16]`, `ccv[4][16][128]` bytes, `used` as a 64-bit mask, `pend`, `echo` (<= 16 x 4 notes outstanding: cap 512), CSL glides (cap 64), the LFO state per instrument (64), the pending-output array sorted by time (cap 4096; the outbox) and an SPSC output ring.
- **Output: a timestamped byte stream.** Records `{int64 frame; uint8 port, len, flags, kind; uint8 b[3]}` (16 bytes) pushed on an SPSC ring (`rt/spsc.h` exists) that the shell's MIDI thread drains. `flags`: `CLEAR` (a STOP marker: drop everything queued for that port that is not yet sent). Port = the letter 0..3 (the shell maps letters to cables; U36 owns `midi.cfg`).
- **The outbox in the core:** with `lead_ms = 60` (default for shells without a recall, i.e. Web MIDI, AMidi, WinRT) the core holds each message in its own time-sorted array until `due - 60 ms`, exactly the web's `MOB` rule; STOP drops what it holds, so `CLEAR` is only informational. With `lead_ms = 0` (shells with a timestamped sender thread and a clear, the existing `io/` helper) messages are pushed at once with their full look-ahead and `CLEAR` is mandatory. The two goldens per case (`native` and `-web`) pin both.

### 3.2 C API (the style of `thunder/render.h`: a C API with no callbacks, the host pulls)
```
typedef struct thunder_midi_msg { int64_t frame; uint8_t port, len, flags, kind; uint8_t b[3]; uint8_t pad[1]; } thunder_midi_msg;  /* 16 bytes */
int     thunder_midi_cfg(thunder_core*, int port, int connected, int clock_on, double gear_delay_ms);   /* 0 ok, <0 error */
int     thunder_midi_set_outbox(thunder_core*, double lead_ms);               /* 0 = immediate + CLEAR; 60 default */
int     thunder_midi_set_latency(thunder_core*, int64_t fx_latency_frames);   /* mastering + safety + PDC, from the core's own mixer */
int     thunder_midi_note(thunder_core*, int ii, int note, int vel /*0 = off*/, int cap);  /* live keys */
int     thunder_midi_raw(thunder_core*, int port, const uint8_t* b, int len, double extra_ms);  /* thru, tests */
int     thunder_midi_panic(thunder_core*);
int64_t thunder_midi_drain(thunder_core*, thunder_midi_msg* out, int64_t cap);   /* count written; the shell calls it every ~1-5 ms */
uint64_t thunder_midi_stats(thunder_core*, ...);                               /* dropped, late, high-water */
```
Timestamps are the core's own audio frame counter at the engine rate (the `frame` the song's notes would be heard on, i.e. including the FX latency and minus Gear delay): `int64` frames, the unit the rest of the core uses; a double of seconds loses nothing at 48 k but frames make the test exact and keep the audio thread integer-only. The `ms` of the ledger = `frame / sr * 1000` (the ledger has fractional ms like 1249.666667; at 48 kHz a frame is 0.0208 ms, so a ledger value is not on the grid: compare with a tolerance of 1 frame + 1e-6 s, or round once, ruling A1).
- **Shell mapping:** each shell keeps a pair `(frame0 <-> host time0)` taken at a device callback (it needs this for audio anyway) and sends a message at `host = host0 + (frame - frame0) / sr + outputLatency`. Web MIDI: `performance.now()` ms (the web's `amap`), `output.send(bytes, ts)`. Android: `AMidiInputPort_sendWithTimestamp(port, data, n, timestampNs)` with `CLOCK_MONOTONIC` ns (`System.nanoTime`), the platform's MIDI service does the waiting (honoured on USB; keep `lead_ms = 60`; there is no clear). iOS / macOS: CoreMIDI `MIDIPacketListAdd(..., timeStamp)` with `mach_absolute_time` units (`MIDISendEventList` on newer OS; clear = `MIDIFlushOutput`), `lead_ms = 0` is possible. Windows: WinRT `MidiOutPort.SendBuffer` has no timestamp; the shell needs its own sender thread (the `io/src/midi.cc` design: sleep to 0.5 ms before, spin the rest, `midiClear`) and `lead_ms = 0`. The existing `io/` helper takes `midiSend(port, bytes, atNs)`: the Electron-like shells can use it unchanged.
- **Threads:** `book` / `onStep` on the audio thread only; `cfg`, `set_*`, `note`, `raw`, `panic`, `drain` from other threads go through the control queue / the ring like every other core message (no locks, no allocation).

### 3.3 The build, in order (small, each testable)
1. Port `msend`, `moNote`, `moPlay`, `offNote`, `bend*`, `moCmd`: the note / CC / PGM / bend cases (`mono-notes` ... `slide-arp`), ctest `midi_ledger`. 2. Clock, SPP, Stop, port toggle (`tempo-*`, `start-*`, `song-end`, `loop`, `clock-port-toggle`). 3. LFO, CSL, echo, ARP return, release / panic. 4. The C API + drain + the `lead_ms` outbox; `-web` goldens. 5. Clock-in follower and a second ledger tool for it (phase 2).
The test reads `midi-ledger-<case>.json`, builds the song from `setup`, drives `Seq` + `MidiSched` with the page's cadence (a 25 ms pump) and compares.

### 3.4 Ambiguities that need a ruling
- **A1. Comparison tolerance and "pump phase".** Messages from the sequencer events (`k = ev`, `release`, `stop`, `start`, `panic`, `join`) are exact functions of the event time: compare to 1 frame. But `clock` under a tempo change, `lfo`, `ramp`, `echo` and anything cut by a STOP depend on WHEN the pump runs relative to the steps (25 ms ticks on the page; a block, ~2.7 ms, natively). Proposal: exact for the `ev` kinds; for `clock` at constant tempo exact; for `lfo / ramp / echo` compare the sets of (time, bytes) up to the STOP time (the booking horizon differs) with 1 frame tolerance; for the clock around a tempo change see A2.
- **A2. Tempo change and the clock (B2).** The web's ticks around a tempo change are irregular (jitter up to 14 ms, out of send order). Proposal: FIX in the core (integrate the tempo map: a tick's time from the anchor at or before it, forward, so the stream is monotonic and regular); then the `tempo-clock` / `tempo-live` goldens are compared only on the ticks away from the change (> 100 ms) plus a rule "monotonic, interval within the two tempos". The alternative is bug-for-bug, which needs the web's 25 ms pump phase reproduced in a block-driven core: not worth it.
- **A3. Output latency and `amap`.** The web adds the device's output latency inside `amap`. Proposal: the core's `frame` excludes the device output latency (the shell adds it, as it does for the audio the user hears); the core includes the FX latency (`moFxLat`: it is the core's own mixer / mastering). Needs the mixer to expose total latency in frames (the `pdc` code has it).
- **A4. Who owns the port table** (`midi.outIds / clk / lats`, the saved settings): U36 / the shell (CORE-BRIDGE `midi.cfg {outs, clockOut, clockIn, gearDelay}`); the core only holds `connected / clock_on / gear_delay` per letter. Confirm.
- **A5. Bend range.** The web never sends RPN 0, so `pbr` is only the scale. Keep (bug-for-bug), or add an optional "send RPN 0 on first bend"? Proposal: keep; add as a later opt-in.
- **A6. FX latency cache (250 ms).** Native: read each block from the mixer (free); the web's 250 ms staleness only matters at plan changes. Proposal: no cache.
- **A7. Hidden page / handover** rules (`MOLED`, the 1.2 s look-ahead, `seqHandover`) are web-only and are NOT ported.
- **A8. CC / bend state across PLAYs.** `mx.ccv` and `mx.used` survive STOP (B6); `mx.bend` does not. Keep both (bug-for-bug) unless ruled otherwise.
- **A9. Where the SPP comes from.** `sppFor` runs a whole silent sequencer (`makeSeq(..., sim)`) on the page, over the song block (up to 20000 steps). Natively: the host computes it on the control thread with a `Seq` (allocation allowed there) when `play` has a start row; same as U34's pattern. Confirm.
- **A10. Clock-in** (follower) is core-side phase 2 (needs the anchor) and the Settings for it come from U36; confirm the split.

### 3.5 Suspected bugs in the web app's MIDI out (for the owner)
- **B1. A note with volume 00 (or a HUMAN VEL that rounds to 0) sends nothing and does not end the note before it.** `moNote` returns at `:16927` before `moOff`, so on a mono track the previous gear note keeps ringing through the silent row until the next note or OFF (ledger `velocity`: the note 64 started at row 4 rings through row 5, ended by row 6). On a pad the same row is silent and the pad's own voice is replaced. The native port follows the page; a fix would be `moOff(t, e.t)` first.
- **B2. A tempo change makes the MIDI clock irregular.** Ticks are placed relative to the newest `beat` anchor, which is up to 250 ms AHEAD of the tick, using the NEW bpm backwards, while earlier ticks were booked at the old tempo: in `tempo-clock` (TPO 90) one tick is booked 34.7 ms EARLIER than the one before it, and the intervals around the change are 20.8, 6.9, 13.9, 13.9, 6.9, 20.8, 27.8 ms (sorted by timestamp). Gear that follows the clock sees a jitter of about 14 ms at every tempo change, and a live tempo change does the same (`tempo-live`). Proposal A2.
- **B3. Start is not Gear-delayed but the first note is**, so with a positive Gear delay the first note arrives BEFORE the Start (`fx-latency`: note-on at 667.6 ms, Start at 671.6 ms with a 4 ms delay). A sequencer that arms on Start may miss the first step. (Intended for "the gear's own latency" on notes, but the clock should probably move with them, or Start must not trail the first note.)
- **B4. Two tracks on one port and channel cut each other's notes** (`chan-share`); the app does not warn (the Settings line only checks missing cables).
- **B5. `mx.ccv` is never cleared** (`moRelease` `:17188` clears held, pend, bend, ramp, ccr, echo, not `ccv`), so the first CSL glide of the next PLAY starts from the value the PREVIOUS run (or KEYS PLAY, `:16640`) last sent, which the gear may no longer have (a patch change, another sequencer).
- **B6. `mx.used` is never cleared**, so every STOP sends All Notes Off (and re-centre) on every port+channel used since the page was loaded, including instruments the song no longer uses; harmless but noisy, and a spent channel shared with other gear gets a 123 on every stop.
- **B7. `moClock` is capped at 512 ticks a call** (`:17068`): after a main-thread stall longer than ~21 beats' worth of time the missing ticks go out together in the next calls with timestamps in the past (clamped to now), a burst. A hidden page's pump is throttled, which makes this reachable. In "Audio thread" mode a pad note more than 0.15 s late is dropped (`:23827`), but `moEv` runs BEFORE that test (`:23815`), so the MIDI note of the same row is still sent (late, clamped to now): after a main-thread stall the gear plays notes the pad skipped.
- **B8. STOP's `[0xFC]` is timestamped after the last booked tick**, but `moRelease` clears queued ticks first, so with a native port the Stop follows ticks that never went out (`start-stop`: the last tick sent is at 1895.5 ms, the Stop at 1938.2 ms): a gap of two missing ticks before the Stop. Harmless; noted for the A1 rule.
- **B9. `release` sends a second note-off at `h.t + 0.001` for a note that had not started**, after the clear removed its note-on: a stray off. Harmless.
- **B10. No bank select and no RPN for bend range** (A5): a program change goes to bank 0's program, and a song using PBN / PVB / slides at `pbr` 12 sounds wrong on gear left at 2 semitones. Documented rather than bug.
