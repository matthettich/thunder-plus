# U23: layer types standard + wavetable + PD + chip + pwm + sample / grains + vint, and click

Extends U22's engine (`native/core/src/engine/`). **Bit-exact**: 61 of 61 factory voices of beta's `tests/golden/engines.json` whose layers are of U22's or U23's types (and at least one of U23's) give beta's hash; 311 of 311 direct cases against the real JS (committed Linux hashes on every platform; the local Node comparison only on x86-64 Linux). Gate command: `native/tools/parity.sh u23`.

## What is where
- One file per layer type, `native/core/src/engine/layer_<type>.cpp`: `click`, `wavetable`, `pd`, `chip`, `supersaw`, `pwm` (with the built-in cymbal, `pwmDefault`), `sample` (plain + SAMPLE LOOP: forward with crossfade, ping-pong), `vint` (the vintage sampler modes of a sample layer), `grains`. `layers.h` declares them; `layer_u23.cpp` is the dispatcher (`LayerOsc`) and the layer's JSON fields; `layer_params.h` is `EngU23` (the wavetable / vint / loop fields and the sample pointer: `EngLayer::u23`).
- Shared files touched, each with the smallest edit: `engine.h` (include, the eight `LType` names, `EngLayer::u23`), `engine.cpp` (include, the name table, `eng_init` builds the PWM cymbal, `Osc` has a `LayerOsc x` and a `blk`, `renderLayer` calls `osc.blk(inc)` where the JS calls `osc.blk(t, e0, inc)`), `engine_json.cpp` (one call), `core/CMakeLists.txt` (one `target_sources` line), `tests/CMakeLists.txt` (a block at the end), `tests/rt_harness.cpp` (`run_engine_u23` + one line in `main`), `tools/parity.sh` (u23).
- Test and reference: `native/tests/test_engine_u23.cpp`, `native/tools/engine-u23-dump.mjs` (imports `engineOf` from `engine-dump.mjs`, which is unchanged), goldens `native/tests/golden/engine_u23_voices.json` (the 61 voices), `engine_u23_voices_golden.inc` (beta's hashes, copied), `engine_u23_golden.inc` (the 311 direct cases' hashes).
- ctest: `engine_u23_ref` (Node makes the reference, about 10 s), `engine_u23`, `engine_u23_golden_current` (Linux), and `rt_core` now also runs `rt_engine_u23` (allocation guard).

## Decisions
- **supersaw is in this unit** (the inventory lists it under "standard"; U24's list does not have it). `chord` and `karplus` are U24's (additive family / KSString), `chaos` and the wasm engines are not here.
- **The sample is the caller's**: `EngLayer::u23.smp / smpLen / smpSr` point at float data the layer does not own (`sample.data` / `sample.sr`). `EngSampleBank` (layers.h) is the control-thread helper that owns data read from JSON `{"sr", "data": [...]}` for the tests and a loader. Stereo samples (`.r`) are not here (as in U22).
- **vint allocates**: `vintData` makes a Float32Array of the machine-rate copy; here `VintOsc` holds a `std::vector<float>`, built in `init` (the JS caches it on the sample; the copy is a pure function of the sample, so no cache). A sample layer with `vint > 0` therefore allocates: offline render only, not under the allocation guard. Every other layer type of this unit renders without allocating (the wavetable's 1025-float table is inside the oscillator on the stack; `eng_init()` builds the PWM cymbal once; `rt_engine_u23` proves it). A sample rate of 0 or negative (vint's copy would be `new Float32Array(Infinity)`, a JS exception) gives a silent layer.
- **JS quirks kept**: indices past a typed array read as undefined (NaN in arithmetic): a **wavetable with negative Bend can produce NaN** (`1 - pow(1 - p, e)` rounds to exactly 1 near the end of a cycle, so `x = 1024` and `tab[1025]` is undefined: the whole voice goes NaN from that sample on). It is in the web app too (checked in Node: `wtBend -0.83` renders NaN at sample 4500 of a case). Ported as is; **not fixed** (web code is not ours today). A sample layer with Position below 0 reads undefined as well.
- `chip` and `pd` switch on a wave number that can be NaN or negative for a control outside 0..1: the NaN / negative case takes the JS's own branch (noise for chip, the `default` branch for pd).

## Not in the direct cases, on purpose
- Outputs whose NaN comes from the CPU (supersaw with negative Detune: `Math.pow(negative, 1.6)`; pwm with negative Shape: `-0 / 0`): the NaN's sign bit is the platform's (x86 negative, arm64 positive), so the bytes differ by platform whatever the port does. The generator keeps those controls inside 0..1.4 (see the comment in `engine-u23-dump.mjs`). NaN from reading past an array (undefined) is a positive NaN everywhere and IS in the cases (negative Bend, negative Position).

## Mutation checks done (each makes the gate fail)
wavetable sub rate, bend exponent, harmonic limit; pd resonant-wave constant; chip 12.5 % duty; supersaw detune constant; pwm DPCM step, 1-bit duty; sample ping-pong, loop crossfade; vint 'SP 12-bit' rate, vint colour; grains jitter; click half-cycle. The factory voices alone catch click, chip, supersaw and (by the one wavetable and one pd voice) little else: the direct cases carry the rest.

## Not sure / left
- Factory voices that MIX U23 and U24 layer types (for example FM layers beside clicks, 100+ of the 2142) are in neither unit's gate until both are merged: whoever merges second should regenerate the fixtures with the types of both sets (`--fixture <beta>` in both tools) and check the union.
- There is no factory voice with a sample, grains, pwm or vint layer in `engines.json` (no samples in the golden's Node): those four are gated by the direct cases only (samples made with + * / so they are the same on every platform), not by a beta hash.
- `blk` is a hook only the wavetable uses; the JS calls it for every oscillator with `(t, env, inc)` (the FM types use `t` and `env`: U24 must extend `Osc::blk` and the call in `renderLayer`).
