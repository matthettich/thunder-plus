**How it was told apart** (`native/tools/psyn-strict-wasm.sh`, a diagnostic that is not part of any gate): the same pin built to wasm with the web's flags plus `-fno-associative-math` (an existing build of that exists on the session's disk too): 433 of 507 cases bit-exact; with `-fno-fast-math -ffp-contract=off`
(what the native host is): **464 of 507 bit-exact, 37 within -100 dB, 6 outside (`pre_pgloss_23`, `pre_pgloss_24`, `hi_pgloss`, `hi_porbit`, `pre_pfreeze_6`, `hi_pfreeze`)**. For the lead: the web's CPU cost of `-fno-associative-math` was measured (TODAY.md, 16 Nov) and the owner declined it; the owner's other route (an explicit lane order in the oversampler's FIR, pump source `common/dsp/Oversampler.hpp` lines 55 and 75) would make TRACT, ORBIT (7 of 8), STRIKE and the FREEZE pair exact without a flag.

## Findings in the pump source (the owner's own plugin code: he will want to fix it upstream)
1. **WOB, `plugins/wob/WobEngine.hpp`, `synthSample()`, the SUB oscillator: reads past `sinT` (4097 floats).** `subPh += inc / (set.subOct ? 4.0 : 2.0); if (subPh >= 1.0) subPh -= 1.0;` wraps once, and `tab(subPh)` then reads `sinT[(int)(subPh * 4096)]` and `+ 1`.
   Trigger: inc / 2 above 1, i.e. a pitch above twice the sample rate (found by the fuzz: MIDI note 127, Octave +2, Tune 12, Wobble pitch 12 at 22050 Hz with Sub above 0). The index is unbounded: AddressSanitizer SEGV (`WobEngine.hpp:338`); in the web wasm the same read goes up to the end of the 16 MB memory and traps (a RuntimeError in the render Worker).
   Patched for host builds only in `third_party/prepare-pump.sh` (a copy in the build folder; `subPh -= std::floor(subPh)`, as the partials' phases do two lines above; for subPh in [1, 2) floor is 1, so every sound that did not read outside the table is unchanged: the 507 cases do not move). The wasm builds are not patched (their bytes stay the pin's).
2. **Allocation in the render path: `SynthBase::run` (`wasm/pump_synth.cpp`) sorts the queued events with `std::stable_sort`, whose temporary buffer is an allocation.** A block WITH an event allocates once (measured in `rt_pumpsynth`: 1 `operator new` per block with a note off, all 13 instruments); a block without events allocates nothing (13 instruments x 600 blocks under the guard). For the live lanes: a block with a note on / off is a real-time violation until that sort is replaced (an insertion sort on the 512-entry queue, which is already nearly sorted).
3. FREEZE's built-in sources are built on the first `process()` that needs each (`source()` in `pump_synth.cpp`: about a second of work, a static cache of `shared_ptr`s): `PumpSynth::builtins()` builds all seven on the control thread (the harness and the fuzz call it).
4. (From U03, unchanged) `wasm/pump_synth.cpp` defines `struct std::mutex` in `namespace std` for wasm.
