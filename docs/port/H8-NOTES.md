# H8: files, single instance, `.thunder` association, check-only updater, Mac audio-input entitlement (native desktop shells)

Branch `n4/h8-files-updater` (PR into `native`). `native/core` and every audio-thread file are untouched. Platform-neutral logic is tested on Linux (`ctest -R desktop_`); the Windows and Mac code compiles and is exercised only in CI (`native-desktop.yml`).

## 1. Files (S-1) — already in H6, re-checked, nothing to add
`file-open`, `file-read`, `file-save`, `file-saveas`, `out-pick`, `out-write`, `out-show` are real in both shells (H6): system Open / Save dialogs, `.thunder` / `.json` only for projects, `.wav` / `.zip` / `.mid` only for renders, save writes `p.saving` then renames, and the S-1 rule (a path is read or written only if a dialog returned it, `openPath` handed it over, or it is in the persisted last-64 list `allowed-paths.txt`; anything else is `{error:'not allowed: ...'}`, the shape the page already handles). H8 adds the OS hand-offs to that list: a file from the command line, a second launch or a Finder open all end in `DesktopApi::openPath`, which allows exactly that path. Before it gets there the shell checks it is an existing `.thunder` / `.json` regular file (`tpd::openablePath`), stricter than Electron's `open-file`, which passed any path on. Tests: `test_desktop_api` (S-1, unchanged, green), `test_launch_args`.

## 2. Single instance
- **Windows** (`win/main_win.cpp`): named mutex `Local\ThunderPlusNative.SingleInstance` (per login session). A second launch finds the first copy's window (class `ThunderPlusNative`; retries for 6 s while it opens), sends `WM_COPYDATA` (magic `TPD1`, payload `TPD1\n<absolute UTF-8 path>`; path resolved against the second copy's own folder), and exits 0. The first copy decodes it with `tpd::handoffDecode` (magic, size <= 32 KiB, no NUL, an existing `.thunder` / `.json`), restores and focuses the window, and calls `openPath`. If no window answers in 6 s the second copy runs on as a copy of its own rather than doing nothing. Not applied under `--selftest`, `--cdp-port` or `--allow-multiple`.
- **Mac** (`mac/main_mac.mm`): LaunchServices already keeps one copy of an app opened from the Finder. A copy started from a terminal (or `open -n`) checks `NSRunningApplication` for its bundle id before the run loop; if another copy runs it asks it to open its file with `open -a <that bundle> <file>` (arrives there as `application:openURLs:`), activates it and exits. Not applied under `--selftest` / `--allow-multiple`.
- **Both**: `--open-log <file>` is a test hook, every path handed to the page is appended to the file; CI uses it.

## 3. `.thunder` association
- **Windows**: no installer exists yet, so the shell writes the same per-user keys electron-builder's NSIS writes (`HKCU\Software\Classes`: `.thunder` -> `ThunderPlus.Project`, `Content Type application/x-thunder-plus`, `OpenWithProgids`, the ProgID with `DefaultIcon` and `shell\open\command` = `"<exe>" "%1"`) when run as `Thunder Plus.exe --register-file-type`; `--unregister-file-type` removes them (the `.thunder` key only if it still points at us). The list is `tpd::fileAssocEntries` (tested). **What the installer must do:** run `"<installed exe>" --register-file-type` as the installing user at the end of install and `--unregister-file-type` at uninstall (or write the same keys under HKLM\Software\Classes for an all-users install). Windows 10/11 keep their own "UserChoice" if the person picked another app for `.thunder` before; the person then picks Thunder Plus once in "Open with".
- **Mac**: `mac/Info-extra.plist` (merged into Info.plist after the build by `mac/plist_extras.sh`): `CFBundleDocumentTypes` (extension thunder, role Editor, rank Owner, mime `application/x-thunder-plus`) and an exported UTI `com.matthettich.thunderplus.project` conforming to `public.json`. The shell handles `application:openURLs:` and `application:openFile:` (both validated by `openablePath`). LaunchServices learns the association when the app is first registered (copied to /Applications or opened once).

## 4. Updater (check only, no download, no install)
`shared/update_check.{h,cpp}`, wired into `DesktopApi` (`upd-state`, `upd-check`, `upd-act`, the `thunder:upd` push), HTTP from the platforms (`IPlatform::httpGet`: WinHTTP / NSURLSession, HTTPS only, 4 MiB cap, a few seconds' timeout).
- **Feed**: GitHub Releases of `matthettich/thunder-plus` (`/releases?per_page=30`), the same source as Electron's `ghCheck` fallback. Electron's electron-updater reads the same repo's atom feed. The list (not `/releases/latest`) is used so a newest release that is not eligible cannot hide an eligible one.
- **Offered**: not a draft, not a pre-release, tag exactly `v<digits>(.<digits>)*` (no suffix); the highest version of those; newer than the app's version (a `-suffix` build sorts below the same number). `android-beta-test` (rolling pre-release) can never be offered, with or without the pre-release flag; a release URL outside the repo is replaced by the releases page.
- **Page path (unchanged page)**: state `{version, avail, ready:false, notifyOnly:true, dl:null, file:null}`, push `thunder:upd` on a new `avail`; the page shows Update + toast; Update (`upd-act`) opens the release page in the browser (Electron's Mac / portable behaviour minus the download). "Check for updates..." (`upd-check`) answers `true` (feed read) / `false` (offline) and shows a message box like Electron's ("You have the newest ...", "Thunder Plus X is out", "Couldn't check").
- **Automatic checks**: 8 s after start and every 4 h (Electron's timings), only in a release build: off for `--selftest`, `--null-audio` and any version with a `-` (CI builds are `0.0.0-native.N`). The menu check still works there.
- Tests (`test_update_check`): version order, tag rule, feed filtering (pre-releases, drafts, `android-beta-test`, garbage), the channels with a fake platform, 8 s / 4 h timers, close during a check.

## 5. Mac hardened runtime + microphone
`NSMicrophoneUsageDescription` was added in H7 (`mac/add_mic_key.sh`). H8 adds `mac/Thunder.entitlements` (`com.apple.security.device.audio-input` only; not sandboxed, no JIT in the app process) and `mac/sign.sh <app> [identity]` = `codesign --options runtime --entitlements ...` (identity `-` = ad hoc, what CI does; a Developer ID identity for a release, then notarise). CI checks the entitlement and the `runtime` flag on the signed bundle, then runs the selftest on the hardened build.

## Needs the owner's hardware or signing
- Windows: double-click a `.thunder` in Explorer after `--register-file-type`; the first run of `WinHTTP` against the real GitHub feed (CI runs with no network check); real MessageBox look.
- Mac: Finder double-click / Dock drop of a `.thunder` file (association registration by LaunchServices); the microphone prompt under the hardened runtime with a real input (the 28 inputs); an Apple Developer ID certificate and notarisation (`sign.sh <app> "Developer ID Application: ..."`, `notarytool`); the real update check.
- Windows code signing (Authenticode) is not part of H8.
