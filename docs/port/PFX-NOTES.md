## Decisions (contract-keeping choices made unattended)
1. `EngRenderOpts::libFx` (default true). The beta golden voices were made by a Node WITHOUT the effects libraries (`fxReady` false: reverb / lofi / tape / crush ... pass the sound). Those old golden tests (test_engine, _xeng, _xeng2, _xeng3, _u23 .. _u26) set `libFx = false`: their goldens do not move. Every production caller gets the effects.
2. Effect statics (libc rand, stmlib's generator, DaisySP myrand) are per wasm instance on the page and the page shares ONE tfx instance among all pads of a render worker, so its pad effects depend on what rendered before. Native: every pad effect starts from a fresh instance's values (the same ModuleState the track host gives a host). The reference tool does the same (a fresh engine per case).
3. MODFX seeds: the page draws them from the worker's global counter (order dependent). Native: a fresh SeedCounter(12345) per effect. Modules that draw seeds (noise, chaos) are bit-exact against a fresh page engine; a pad made on the page after other renders may differ in the random part only.
4. HARDENING (the page's UI cannot make these): a saved control outside its row's range is clamped to the page's min / max (padfx_ranges.inc, generated; in pad_fx_lib); an effect with a ROW control the saved object LACKS (NaN on the page, which runs the wasm off its tables: found as a segfault in Verbity2 / room with `{type:'room'}`) is refused = the sound passes, as for an effect that is not ready. Not applied to MODFX (the modules' ports take any number, fuzzed: 682 runs, no crash).
5. Chorus: the page's wrapper calls DaisySP's Chorus in 4032-sample chunks and sets the knobs once per chunk, which is audibly different from every 128 (max difference 0.14): native runs the tfx twin in the same 4032 chunks (and scales its x1.4 to the page's x1.6). Crush, density, tape likewise reuse the tfx twin with the page's own blend arithmetic.
6. Rings and Clouds: the page's own wrappers (w_rings.cc, w_clouds.cc: resample to 48 / 32 kHz, 96-sample chunks, the Clouds freeze after the sound) as objects in `core/dsp/padfx_mi.cc`, a separate dsp_group that is NOT part of the wasm build (tfx.wasm's link unchanged).
7. `tgate` uses the voice render's bpm (`EngRenderOpts::bpm`, the page's songBpm()); MODFX modules get tempo = bpm, playing, startN 1 (modFxRun). `spectral` is pulled back by its latency (2048) when fully wet, as the page does.

## What the page does (index.html, ENGINE block)
- `renderVoice` -> `renderLayersOnly` (layers) / `padFx` (Blip and every X engine that is not `live`: `engFx(V)`). Bass, Voice, Acid and Machine return before any pad effect: they are DRY on the page.
- Order: the voice is rendered (N samples), then `ext = Float32Array(min(N + round(V.tail * sr), sr * (SMP_MAX + 12)))` holds it with zeros after; then for each `f of V.fx` with `f.on && FX[f.type]`: `buf = applyFx(f, buf, sr)` IN LIST ORDER (offline, whole buffer, one effect after the other, mono in / mono out). Then trim (`end` while |x| < 1e-4) and a 2 ms fade.
- Tail: only the voice's own `tail` (default 2 s) gives room, PLUS the two pitch effects (pdelay / preverb) which lengthen the buffer themselves (`N = a.length + tail`). Every other effect keeps the length (the library effects ring out only inside `tail`).
- Dry/wet: each effect's own `mix` (or `wet`, `blend`). The three reverbs `reverb`, `space`, `room` are run fully wet in the wasm and blended by `rvMix(mix)` in `txRun` (`out = a * dry + wet * w`, REVERB MIX).
- A value a saved voice lacks is `undefined` on the page (no defaults are filled at load; `freshFx` only fills a NEW effect): it reaches the maps as NaN.
- `fxReady(f)` false (library not loaded) = the sound passes. The native core has the libraries, so native = "ready".
- A new effect row is added by the UI to at most 6 per pad (`v.fx.length >= 6`); the core's EngVoice holds 8.
