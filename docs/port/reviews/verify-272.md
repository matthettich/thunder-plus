## Findings

* **F1 (must fix): the idle skip is not bit-identical.** It drops the last `lat` samples (about 26-31) of a voice's last block. The shell runs `lat` samples ahead of the mixer, so when the core goes idle the ring still holds rendered-but-undelivered samples; the node is skipped from the next quantum (`runNode`), and `fastForward` zeroes the ring (when `nb*kBlk >= kRing` it zeroes the pending region too). Reproducer (my harness `vfy_pool`, delta-debugged): ONE bass note at t=1.726963 (rate 0.612, col 2) + its off at 1.795206, pad bass rel default, track 0: skip ON vs `setIdleSkip(false)` differ in 26 consecutive samples at frame ~182272 (3.8 s), skip gives 0 where processing gives -2.19e-06 ... -9.8e-08. Second reproducer: mach pad, one note t=0.629775 on track 1 + `stopAll(2.241293)`: 15 samples, max 8.2e-07. Over 300 random scripts (see item 1(b)) 14 differ (bass, acid, mach; vox 0), every one a tail of 1e-7 .. 2e-6 (-114 dBFS and below), stats identical. Inaudible, but the claim and the test bar are "no sample". The builder's `test_live_idle` (305 pairs) does not see it because its scripts compare after the stretch and its compare window... (it passes: its scripts end notes with a long release the pool compares through, but tails are compared only at quantum level where the dropped samples are the last 26 of a quantum that it only memcmp's when equal... not investigated further). Scratch fix tried (not committed): skip only after the core was idle for one whole quantum (`idleSeen`): 14 -> 1 differing script; the remaining one is host block size 1 (quantum < lat), so the rule must be "idle for at least lat + kBlk samples", not "one quantum".
* **F2 (must fix / owner decision): the "vox held" parity "fix" is not a fix and the stated cause is wrong about the page.** The PR changes no engine code for it: the pool's rate lane still starts at 0 (`AutoN<kAutoRate> rate{0}`) and the two failing scenarios were rewritten to start at sample 0 (`held` scenario) so that the difference does not show. The notes say "the page's AudioParam default is 0". The page's `rate` AudioParam default is **1** (`index.html:22571` bass, `:22656` vox, `:22738` acid/mach: `{name:'rate', defaultValue:1, ...}`), the builder's own table in `LIVE-ROUTE-NOTES.md` 2a says `rate a 0..256 (1)`, and nothing in the page sets `rate` before a node's first note (node made at `index.html:21685`, `rate` only touched in `bassNote`). With THUNDER CORE driving the node, `__tcOv` (core-processor.js:157) uses the page's own AudioParam value for every sample before the override's first event (`A.from`): that is 1. So the JS rule (seqRender, idle default 1) matches the page and the POOL (0) is the inconsistent side: the vox core latches its pitch `lf_` from `rate` in idle blocks, so a first vox note after idle but not at sample 0 glides from log2(20) in the pool and from log2(261.6) in the page.
