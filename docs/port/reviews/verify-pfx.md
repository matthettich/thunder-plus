# Independent verification of PR #314 "PFX: pad effects in the core pad render"

Branch n1/pfx-pad-effects, head f897023672f2e9597e1b68734dfd3cab7b8e261f (base origin/native 0f746352). Verifier: Claude Opus 5.5, independent; nothing in PFX-NOTES.md was trusted without a check. Reported, not fixed.

## VERDICT: MERGE AFTER FIXES

The port is faithful where it is tested: the golden tool really is the page's code, the mapping matches the page line by line, 106 of 134 cases are bit-exact and the rest are inside measured gates, the full Release ctest (240 tests) passes, ASan / UBSan are clean on test_padfx and on 7038 hostile cases. But there is one UI-reachable hard crash (F1, SIGFPE in Beads) that does not exist on the page, a claimed build-hygiene fix that is not in effect (F2), and two behaviours that no test pins (F3). Fix F1 and F2 before merge; F3 and F4 can follow in the same PR or the next.

## Findings, by severity

### 1. HIGH: Beads with Tail = Hold and Size at max kills the process (SIGFPE), the page does not
- `beads` with `freeze: true` and `size >= 0.995` (the Size slider at max; the page's own map caps size at .995, so 1 and .995 are the same) divides by zero in upstream Beads: UBSan says `upstream/eurorack/beads/dsp/delay_controller.cc:277:45: runtime error: division by zero` (`slice_duration = int(clock_.interval(i) * tap_ratio[r])` is 0, then `max_delay_ / slice_duration`). Release build: SIGFPE in `beads::DelayController::RenderInternal<true>` <- `BeadsFx::process` <- `runFx` <- `pad_fx_lib`.
- Repro (pad 5 s, any media): `{"type":"beads","media":3,"freeze":true,"time":0.2,"size":1,"pitch":0.5,"shape":0.5,"density":0.85,"feedback":0.2,"blend":1,"reverb":0.25}`. Needs freeze and size >= .995 together (freeze + size .99: fine; size 1 without freeze: fine); media, time, density do not matter. It needs a pad of a few thousand samples or more (the PR's fuzz uses 6000 samples and all-same hostile values, so it never hit this).
- The page runs the same row through tfx.wasm and returns a finite result (Node, page's own applyFx: freeze true with size 0.9 / 0.99 / 0.995 / 1 all fine). So native diverges from the page by killing the Android pad-render thread (pad_filler.cpp has no handler; a signal is not catchable anyway).
- Fix: guard before the effect runs (in `pad_fx_parse` or the beads map: if freeze and size > some safe value such as 0.99, clamp size), or make the Beads host build robust (slice_duration max 1). Add a regression case (freeze true + size 1, 1 s pad) to test_padfx and make the fuzz vary one control at a time with freeze on. Not checked: whether the track-effect host (fxhost.cpp, Beads id 10) has the same crash with its own map; it is the same class, so it probably does.

### 2. MEDIUM: "padfx.cpp in the -fexceptions list" (commit 4a286053) is not in effect
- That commit only added `src/engine/padfx.cpp` to the `add_library(thunder_core ...)` source line. The `set_source_files_properties(... COMPILE_OPTIONS "-fexceptions")` list (core/CMakeLists.txt lines 9-13) does not contain it. In build-v the compile line of padfx.cpp.o has `-fno-exceptions -fno-rtti` and no override (cengine.cpp.o, for comparison, has `-fexceptions`). padfx_mi.cc is fine (dsp_group appends `-fexceptions`).
- Effect: padfx.cpp allocates a lot (vectors for the whole pad, the Rings / Clouds objects: a 312 s pad through rings peaks at 290 MB, clouds 250 MB). A std::bad_alloc unwinds through frames that have no cleanup (leaks the objects and vectors), and the Android pad_filler.cpp (origin/n1/n2-live-shell) has no try / catch, so the process terminates. engine.cpp and xeng_voice.cpp, which call it, are also not in the list (pre-existing).
- Fix: add `src/engine/padfx.cpp` to the -fexceptions list, and have pad_filler's renderPads catch std::bad_alloc per pad (skip it, as it does for "out of memory" already).

### 3. MEDIUM: two behaviours are not pinned by any test (found by mutation)
- Skipping the spectral latency pull-back (shift 2048 when mix is null or >= 0.999): all 134 cases and the fuzz still pass. spectral's default mix is 0.5 and the seeded alt value is 0.898, so a fully wet Spectral pad (the usual use) is never compared with the page.
- tgate ignoring the voice bpm (hard-coded 120): passes. Every case uses bpm 120 and ELECTRO has no tgate pad. The `EngRenderOpts::bpm` plumbing into tgate and into the MODFX tempo (flex, sgate, retrig, sdelay, filter LFO sync) is untested.
- Fix: add fx_spectral with mix 1 (and null mix), and tgate / sgate / retrig cases at bpm 93 (or any non-120 value), to padfx-dump.mjs cases(); regenerate with --golden.

### 4. MEDIUM: a missing segment key makes native refuse the effect, the page applies it
- Decision 4 refuses an effect if ANY control is absent (the sound passes dry). That is right for row keys (NaN into the wasm maps; the Galactic segfault with `{type:'room'}`), but the page applies the effect when only a segment key written with `|0` / truthiness is missing. Checked with the page's own applyFx in Node: tgate without div / pat, beads without media / freeze, tremolo without shape, ladder without mode, cab without model, xmod without carrier, crush without smooth: all return a processed, finite sound. Native returns the dry sound for all of them. A song saved before a segment existed would sound different native vs web.
- Fix: for keys that are segments (FX[type].segs: model, poly, mode, lofi, freeze, shape, carrier, div, pat, media, smooth) treat absent as 0 (the page's `|0` / falsy); refuse only for missing row keys.

### 5. LOW: input audio with NaN / inf passes through eight effects
- With NaN / inf / 1e30 in the pad audio (not reachable from the page's own render, which does not make them), density, tape, crush, chorus, rings and the REVERB-MIX effects (reverb, room, space) return non-finite samples (`a[i] * dry` blend). The page does the same (`a.map`, `a[i] * dr`), so this is parity. pad_filler already drops a pad with a non-finite sample.

### 6. LOW: the PR's fuzz is weak
- `test_padfx.cpp fuzz()` sets every control to the same hostile value on a 6000-sample pad, only checks that the output length is unchanged (not that it is finite, not time), and only goes through the JSON path. `pad_fx_lib` itself does not clamp (the clamp is in `pad_fx_parse`): called with a hand-built EngFx with a hostile `lv` it segfaults in Galactic (reverb). Only the JSON entry is hardened; fine today because that is the only caller, but worth a comment in padfx.h.
- Without `node` the test registers `add_test(NAME padfx COMMAND test_padfx)` with no reference dir, which then FAILs ("no reference directory") instead of skipping (SKIP_RETURN_CODE).

### 7. LOW / NOTE: tolerances and gates
- pshift -70 dB (measured here -85.7 / -75.0), rings -80 (-106.5 / -88.3), clouds 1.6 int16 steps (default exact, alt 1.5 steps = -69.2 dB RMS), pad_three -80 (-84.8): re-measured, same numbers. They are justified by measurement (tfx.wasm is -ffast-math; clouds output is int16). Margins 5 to 8 dB. A deliberately wrong mapping was caught each time for tfx (eq, pshift, delay, space) and MODFX (param 1), so they do not hide a mapping error of that size. Weak spots: rings_alt did not catch a damping / position swap (-82.9 dB against the -80 gate; rings_def did), and clouds_def did not catch a texture / density swap (clouds_alt did). The clouds gate is absolute, so its sensitivity depends on the case's level.
- Clamping a saved value to the page's CURRENT row range (padfx_ranges.inc) differs from the page for a song saved under an older, wider range (the page passes the value through). Intentional hardening (decision 4); not a bug, but not "bit-exact to the page" for such a song.

### The open item: Beads media 0 (Dirty tape) at about -58 dB
Verdict: ACCEPTABLE, not a mapping bug; the gate and the evidence need a small tightening.
- The mapping is identical to the page: page map `[f.media | 0, 0, f.freeze ? 1 : 0, time, min(size, .995), pitch, shape, density, feedback, blend, reverb, 0]` (index.html 4427); C++ `p[0] = i32(media); p[2] = truthy(freeze); p[3..10] = ...; jmn(size, .995)` (padfx.cpp line 49). The effect object itself is the SAME source file (dsp/tfx/fx_beads.cc) the wasm is built from; `media` goes through the same `(int)(p[0] + 0.5)`.
- The only difference is the build: host effect libs are compiled `-fno-fast-math -ffp-contract=off` on purpose (core/dsp/CMakeLists.txt, U14), tfx.wasm keeps `-ffast-math`. The error measured here: starts at the first audible sample (20294), peak 1.3e-3 on a 0.1 peak signal, relative 0.1 to 0.3 % in both audible segments, no growth: a rounding-class difference, not a swapped or mis-scaled control (which would be tens of percent). Media 2 (alt) is -131.8 dB and media 3 (def) -113 dB, so the other media are fine.
- Two honest caveats: (a) rv_beads_media1 (Clean tape) is VACUOUS: the page's reference for it is all zeros in the 30000 samples (the tape delay is longer than the case), so its "exact" compares silence with silence; media 1 has no real coverage. (b) the -50 gate leaves only 8 dB over the measured -58, so a small Dirty-tape mapping error would pass. Suggested follow-up (not blocking): give media 0 and 1 a longer pad / earlier hit so media 1 produces sound, and note that a tfx.wasm built without -ffast-math would show whether media 0 goes exact.
