## Partial findings (update, ~1h35)
- F1 (HIGH, found): a UI-reachable pad state crashes the process. `beads` with `freeze: true` and `size >= 0.995` (the Size slider at max with Tail = Hold; the page's own map caps size at .995) raises SIGFPE (integer divide) inside `beads::DelayController::RenderInternal<true>` via `BeadsFx::process` <- `runFx` <- `pad_fx_lib`. Repro (native/build-v + a 6-line harness): `{"type":"beads","media":3,"freeze":true,"time":0.2,"size":1,"pitch":0.5,"shape":0.5,"density":0.85,"feedback":0.2,"blend":1,"reverb":0.25}` on a 5 s pad. The page runs the same row through tfx.wasm and returns normally (checked with the page's applyFx in Node: freeze true, size 0.9 / 0.99 / 0.995 / 1 all ok), so native diverges from the page and kills the app (Android pad render thread). Not found by the PR's fuzz because its hostile values are all-same and the pad is 6000 samples.
- Timing / memory (Release -O3, 2 shared cores with a running ctest): 62 types x default / all-max / all-min at 60 s of pad: slowest 1.6 s (spectral, space), peak RSS 60 MB (rings). 312 s (SMP_MAX + 12) at all-max: clouds 2.3 s / 252 MB, rings 2.7 s / 290 MB, spectral 8.1 s, space 7.3 s, gdelay 7.4 s, stretch 4.2 s, convolve 3.6 s (RSS 120 - 140 MB). No effect takes more than 0.03x realtime. Fine for a phone, but a 312 s pad through rings is ~290 MB in addition to the pad's own buffers (see "not checked").
- Hostile re-run (21112 cases through the JSON parse path: 62 types x 16 hostile values (1e300, -1e300, 1e999, -0, 2^32, null, true, "x", [1], {}) on all controls and on each control alone, each control missing, lengths 0 / 1 / 2 / 95 / 97 / 129 / 4033 / 6000, input audio with NaN / inf / 1e30 / +-1e4, bpm 0 / -5 / 1e9): zero crashes and zero hangs. Findings only with NaN / inf in the input audio: density, tape, crush, chorus, rings and the three REVERB-MIX effects (reverb, room, space) pass NaN / inf through (a[i]*dry blend). The page does the same (a.map / a[i] * dr), so this is parity, not a regression; the pad filler's finite check drops such a pad.
- Note: the PR's `fuzz()` in test_padfx.cpp only checks the output LENGTH (not finiteness) on a 6000-sample pad with every control set to the same hostile value; its clamp lives in `pad_fx_parse`, so `pad_fx_lib` called with an `EngFx` filled by hand (`lv` unclamped) segfaults in Galactic (reverb) with 1e30: only the JSON entry is hardened.

## Partial findings (update 3)
- F2 (MEDIUM, found): commit 4a286053 "padfx.cpp in the -fexceptions list" did NOT do what it says. It only added padfx.cpp to the `add_library(thunder_core ...)` line; the `set_source_files_properties(... COMPILE_OPTIONS "-fexceptions")` list (core/CMakeLists.txt lines 9-13) does not contain it. The compile line of padfx.cpp.o in build-v (build.make) carries only `-fno-exceptions -fno-rtti`; cengine.cpp.o carries `-fexceptions`. padfx_mi.cc is fine (dsp_group builds it with `-fexceptions`). Consequence: a std::bad_alloc from the many std::vector buffers in padfx.cpp (a 312 s pad through rings / clouds peaks at 250-290 MB) unwinds through frames with no cleanup (leaks the Rings / Clouds objects and the vectors), and `pad_filler.cpp` (n2-live-shell) has no try / catch at all, so it would terminate the process.
- F3 (MEDIUM, found by mutation): two behaviours are not pinned by any case. (a) M3, skipping the spectral latency pull-back (shift 2048 when mix is null or >= 0.999): all 134 golden cases and the fuzz still pass, because spectral's default mix is 0.5 and the seeded alt value is 0.898. A fully wet Spectral pad (the usual use) is never compared. (b) M6, tgate ignoring the voice bpm (hard-coded 120): passes, every case uses bpm 120, and ELECTRO has no tgate pad. The `EngRenderOpts::bpm` plumbing into tgate and the MODFX tempo is untested.
- F4 (MEDIUM, found): decision 4 (an effect with ANY absent control is refused, the sound passes) is stricter than the page for the segment keys. The page applies the effect when only a `|0` / truthy segment key is missing: checked in Node with the page's own applyFx: tgate without div / pat, beads without media / freeze, tremolo without shape, ladder without mode, cab without model, xmod without carrier, crush without smooth all return a processed (finite) sound. Native returns the dry sound for all of them. A song saved before a segment existed would sound different. Only row keys can produce NaN into the wasm maps; suggest treating a missing segment key as 0 (the page's `|0`) and refusing only for missing row keys (and the beads / freeze + size case of F1).
- Mutations (5 asked, 15 run; each compiled as an object overriding padfx.o / xeng_voice.o and linked with the PR's own test_padfx object, run against the page references): CAUGHT: M1 reverb-mix blend dropped (6 cases: reverb, space, room def+alt), M2 chorus chunk 128 (chorus def+alt), M4 MODFX seed counter shared across pads (spring_alt, bbd, gdelay, ringmod ... fail), M5 clamp removed (the fuzz segfaults), M7 eq bass/treble swapped (eq_alt only; eq_def is symmetric), M8 a MODFX param left at its default (many alt cases), M9 chorus gain 1.4 (chorus), M10 pshift semitones x1.02 (pshift def+alt: the -70 dB gate is tight enough for a 2 percent error), M11 rings damping/position swapped (rings_def only: rings_alt gives -82.9 dB against the -80 gate, so the alt case is insensitive to it), M12 clouds texture/density swapped (clouds_alt only, -10 dB), M13 REVERB-MIX w=s instead of s*s, M14 delay time exponent .25 -> .3, M15 crush smooth ignored, X1 Machine allowed pad fx (ELECTRO v10, so the engFx rule is pinned for Machine). NOT caught: M3 and M6 (F3).
- Tolerances: pshift -70 (measured -85.7 / -75.0), rings -80 (-106.5 / -88.3), clouds 1.6 int16 steps (default exact, alt 1.5 measured, baseline -69.2 dB RMS), pad_three -80 (-84.8): re-measured here on this machine, the same numbers. Margins are 5 to 8 dB; a deliberately wrong mapping of one tfx (eq, pshift, delay, space) and one MODFX (param 1) was caught each time, so the gates are not masking a mapping error at the size tested. The clouds gate is absolute, so it is only as sensitive as the signal level of the case.
