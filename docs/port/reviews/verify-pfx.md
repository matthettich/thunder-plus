## Partial findings (update, ~1h35)
- F1 (HIGH, found): a UI-reachable pad state crashes the process. `beads` with `freeze: true` and `size >= 0.995` (the Size slider at max with Tail = Hold; the page's own map caps size at .995) raises SIGFPE (integer divide) inside `beads::DelayController::RenderInternal<true>` via `BeadsFx::process` <- `runFx` <- `pad_fx_lib`. Repro (native/build-v + a 6-line harness): `{"type":"beads","media":3,"freeze":true,"time":0.2,"size":1,"pitch":0.5,"shape":0.5,"density":0.85,"feedback":0.2,"blend":1,"reverb":0.25}` on a 5 s pad. The page runs the same row through tfx.wasm and returns normally (checked with the page's applyFx in Node: freeze true, size 0.9 / 0.99 / 0.995 / 1 all ok), so native diverges from the page and kills the app (Android pad render thread). Not found by the PR's fuzz because its hostile values are all-same and the pad is 6000 samples.
- Timing / memory (Release -O3, 2 shared cores with a running ctest): 62 types x default / all-max / all-min at 60 s of pad: slowest 1.6 s (spectral, space), peak RSS 60 MB (rings). 312 s (SMP_MAX + 12) at all-max: clouds 2.3 s / 252 MB, rings 2.7 s / 290 MB, spectral 8.1 s, space 7.3 s, gdelay 7.4 s, stretch 4.2 s, convolve 3.6 s (RSS 120 - 140 MB). No effect takes more than 0.03x realtime. Fine for a phone, but a 312 s pad through rings is ~290 MB in addition to the pad's own buffers (see "not checked").
- Hostile re-run (21112 cases through the JSON parse path: 62 types x 16 hostile values (1e300, -1e300, 1e999, -0, 2^32, null, true, "x", [1], {}) on all controls and on each control alone, each control missing, lengths 0 / 1 / 2 / 95 / 97 / 129 / 4033 / 6000, input audio with NaN / inf / 1e30 / +-1e4, bpm 0 / -5 / 1e9): zero crashes and zero hangs. Findings only with NaN / inf in the input audio: density, tape, crush, chorus, rings and the three REVERB-MIX effects (reverb, room, space) pass NaN / inf through (a[i]*dry blend). The page does the same (a.map / a[i] * dr), so this is parity, not a regression; the pad filler's finite check drops such a pad.
- Note: the PR's `fuzz()` in test_padfx.cpp only checks the output LENGTH (not finiteness) on a 6000-sample pad with every control set to the same hostile value; its clamp lives in `pad_fx_parse`, so `pad_fx_lib` called with an `EngFx` filled by hand (`lv` unclamped) segfaults in Galactic (reverb) with 1e30: only the JSON entry is hardened.
