## Round 2 (verify-283, the lead's rulings): what changed
- ENGINE TIMELINE (F1 F12 F14, departure 10). The engine counts its own frames from 0 (`qFrame_`); every time it sees is engine frame / sr; the host's frame is `engine + off_`. Conversions: `process` sets `off_` at the first call and changes it in `reanchor` (live_host.cpp; nothing inside the engine moves, the buffered quantum is kept); `applyCommands` / `applyOne` judge and convert `at` (host -> engine); `tryStartPlay` converts t0; `post()` converts every record's `f` (engine -> host); `publish()` converts stats.frames. frame0, t0 and `at` above 2^62 are E_ARG. Proved by `live_equals_render` (bit-equal for frame0 0, 37, 2^31, 10^12, call sizes 1..4096, 40 s, no tolerance; a pad whose first sample is not zero; forward and backward re-anchors across a seam equal the uninterrupted render) and `live_transport` (waiting command across a re-anchor, a gap's command, ENDED timer, CLOCK / POS).
- F9: `play()` pushes the Play command first and publishes the snapshot second (room in both rings checked before), and `adopt()` adopts nothing while a play is stalled (only `tryStartPlay` does). Tested with a seam (`setTestSeam`) that runs quanta between the two statements; a mutation back to the old order is killed. The remaining window (a publish landing between step 1 and step 2 of one quantum) cannot be hit from a single-threaded test; the `!stalledPlay_` guard in `adopt()` covers it by construction and its mutation is NOT killed by a test (listed below).
- F2 poll in strict seq order (stable-head re-load); F3 only STATE, HELD, SONG, PADS and fatal ERROR are critical, REANCHOR limited to one record a quantum, CMD one a quantum; F4 `endStopAt_ = max(t0, endT) + 0.3`; F5 the IDLE ack is queued before the song is replaced; F6 control's "playing" = a play outstanding or the published state PLAYING (so a publish in HELD / ENDED / after the timer takes the IDLE path; only `songPublish` depends on it); F7 `build-r.log` removed from the PR and `build-r*.log` ignored; F10 stop and a started play clear the waiting list (`stats.cmds_cleared`); F11 the old Seq's dropped count is read before the adopt; F13 bpm / loop / perf with no sequencer are dropped and counted (`stats.cmds_no_seq`); F15 `alignas(8)` on the record buffers and slots, size asserts for every record; F16 the allocation harness runs stop, a song END (ENDED, timer, STOPPED), HELD, three re-anchors, timed commands, play-over-play; F17 note in `U37-P0-NOTES.md` (P5 work list); F18 `thunder_live_play_opts` has TEST-ONLY `test_once` / `test_sim` (two lines in `play()`), so `live_step_dump` now compares the goldens exactly (all rows of all 30 cases; no 98 % allowance).

## Thread rules as built
CONTROL calls: one thread at a time. AUDIO: `process` only (it allocates nothing: `rt_harness`). CONSUMER: `poll` / `dump_step`, one thread. `statsGet` and `hostStats`: any thread (relaxed atomics). Rings: commands (256), fx params, events (1024), critical events (64), play results (8), song / pads / bus / pdc / master snapshots (16 each). The control side owns every allocation and every free; the audio side only adopts and hands back.
