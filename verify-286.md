Findings
1. native/tests/test_render_api_oom.cpp:~121 (tolerance) - the pump tolerance is weaker than the comment says. The bound is `dl <= g_pumpBytes`, where g_pumpBytes is the CUMULATIVE bytes allocated inside pump_new in that iteration (freed bytes included, a single EQ/verb instance is MBs). In an iteration whose failing allocation was inside pump_new, a leak of ours smaller than that is hidden. Window is narrow (only iterations that fail inside pump_new), but it is not "strict for our own". Fix: bound by bytes still live from pump (track delete of blocks allocated at depth>0), or assert exactly the known case. Read only. Severity: test weakness.
2. Same file: nothing asserts the NUMBER of tolerated pump cases. Today it is 1 (confirmed by running); a regression back to 49 leaks inside pump_new would still pass. Add `CHECK(pumpLeaks <= 1)` (or per-song cap). Confirmed by running/reading. Severity: test weakness.
3. native/tests/test_fxsong.cpp (ELECTRO check, ~line 143): with no pump library the pass condition is `hosted + refused(kRefNoEngine) == held`, but kRefNoEngine is also incremented for ANY failed make (e.g. a MODFX module returning null). On MSVC a broken MODFX creation would be masked as "pump absent". Confirmed by running (no-pump build: 15 hosted + 10 no-engine). Fix: also assert hosted >= the number of non-pump slots. Severity: test weakness. Also: section 3 (pump through host) prints "not run" and passes with no pump; acceptable but it means MSVC CI proves nothing about pump slots.
